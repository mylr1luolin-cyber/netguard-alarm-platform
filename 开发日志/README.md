# 开发日志

本目录用于记录 NetGuard 项目每天的开发进展、决策与待办，保证多人协作时信息透明、可追溯。

## 记录规则

1. **一天一个文件**，命名 `YYYY-MM-DD.md`（如 `2026-11-24.md`）；跨天连续工作可追加到当天文件。
2. 每次开发结束（或每完成一个可交付事项）**立即追加**，不允许事后补记超过 1 天。
3. 每个日志文件固定包含四个区块：
   - **今日完成**：可验收的具体事项（含涉及的文件/接口/命令），不写"写了点代码"这类空话；
   - **关键决策**：为什么这样做、放弃了什么方案，一句话讲清理由；
   - **遇到问题与解决**：报错原文摘要 + 定位过程 + 最终解法（便于下次不再踩坑）；
   - **明日待办**：从大到小排列，标注负责人与预计工时。
4. 待办事项完成后在当天日志中勾选，并在新日志的"今日完成"中引用。
5. 提交代码时日志与代码同一次提交，commit message 形如 `docs(log): 2026-11-24 开发日志`。

## 模板

新建日志时复制以下结构：

```markdown
# YYYY-MM-DD 开发日志

## 今日完成
- [ ] 事项一（涉及文件/接口）

## 关键决策
- 决策内容 —— 理由

## 遇到问题与解决
- 现象：…
  原因：…
  解决：…

## 明日待办
- [ ] 事项（负责人，预计 x 小时）
```
