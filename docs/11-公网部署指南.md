# 11 · 公网部署指南（把 NetGuard 放到另一台服务器，浏览器直接打开）

> 读者：手里有一台能联网的 Linux 服务器（云主机 / 轻量应用服务器 / 实验室机器），想把本项目部署上去，让别人用网址打开。
> 前置：本文只讲**公网这一台机器**怎么从零装好。代码结构、本地开发、内网部署见 `docs/09-部署运维手册.md`；日常发版用 `deploy/deploy.sh`。
> 结论先行：**最快 10 分钟**可以让 `http://服务器IP:8080` 打开（方案 A，不做域名）；**规范做法 30–60 分钟**得到 `https://你的域名`（方案 B，Nginx + 域名 + 免费证书）。

---

## 一、先选路线

| | 方案 A：IP + 端口直连 | 方案 B：Nginx + 域名 + HTTPS（推荐） |
| --- | --- | --- |
| 需要 | 一台服务器 | 服务器 + 一个域名 |
| 访问地址 | `http://1.2.3.4:8080` | `https://netguard.你的域名.com` |
| 耗时 | 约 10 分钟 | 约 30–60 分钟（含域名解析生效） |
| 安全 | 明文 HTTP，8080 直接暴露 | 可上 HTTPS，应用只监听 127.0.0.1 |
| 适合 | 自己演示、课程验收、临时给人看 | 答辩演示、长期放着、给老师发链接 |

两种路线的第 2–7 步完全一样，差别只在第 8 步（Nginx）和第 9 步（域名证书）。可以先用 A 跑通，再升级到 B。

---

## 二、服务器怎么选

| 项目 | 建议 | 说明 |
| --- | --- | --- |
| 配置 | 2 核 2G 起 | JVM 堆 1G + MySQL 约 400M，1G 内存会吃紧（见 6.6 加 swap） |
| 系统 | Ubuntu 22.04 / 24.04 LTS | 本文命令按 Ubuntu 写；CentOS/Rocky 把 `apt` 换成 `dnf`，systemd 部分通用 |
| 磁盘 | 40G 起 | 系统 + JDK + MySQL + 上传图片 + 日志 |
| 带宽 | 3–5 Mbps 够用 | 页面本身很小（首屏 < 300KB，ECharts 本地 1MB，gzip 后约 300KB） |
| 地域 | 国内 or 香港/新加坡 | **国内服务器绑域名必须 ICP 备案**，否则 80/443 会被拦；只求能打开，用香港/新加坡轻量最省事 |

买的时候注意两点：

1. **安全组 / 防火墙**是云厂商控制台里的东西，和系统里的 `ufw` 是两套，都要放行；
2. 记下公网 IP、root 密码（或密钥），后面全要用。

---

## 三、第 1 步：开放端口

云控制台 → 服务器 → 安全组（或"防火墙"）→ 添加规则：

| 端口 | 协议 | 来源 | 用途 |
| --- | --- | --- | --- |
| 22 | TCP | 你的公网 IP（或 0.0.0.0/0） | SSH 登录 |
| 80 | TCP | 0.0.0.0/0 | HTTP（方案 B） |
| 443 | TCP | 0.0.0.0/0 | HTTPS（方案 B） |
| 8080 | TCP | 0.0.0.0/0 | 仅方案 A 需要；上了 Nginx 后建议删掉 |

> 只开需要的。数据库 3306 **绝对不要**对公网开放。

## 六、第 4 步：装 MySQL 8 并导入数据

### 6.1 安装

```bash
apt install -y mysql-server
systemctl enable --now mysql
systemctl status mysql --no-pager | head -5
mysql --version   # 8.0.x
```

### 6.2 建库建用户

Ubuntu 的 MySQL 默认 root 走 `auth_socket`（本地 `sudo mysql` 免密），项目要用密码登录，所以给应用单独建账号：

```bash
sudo mysql
```

在 `mysql>` 提示符里执行（把 `换成你的强密码` 换成真实密码，只允许字母数字，避免 shell 转义麻烦）：

```sql
-- 应用账号，只给 netguard 库的权限
CREATE USER 'netguard'@'localhost' IDENTIFIED WITH mysql_native_password BY '换成你的强密码';
CREATE USER 'netguard'@'127.0.0.1' IDENTIFIED WITH mysql_native_password BY '换成你的强密码';
GRANT ALL PRIVILEGES ON netguard.* TO 'netguard'@'localhost';
GRANT ALL PRIVILEGES ON netguard.* TO 'netguard'@'127.0.0.1';
FLUSH PRIVILEGES;
EXIT;
```

> 为什么要建两条：JDBC 连的是 `127.0.0.1`，MySQL 可能按 `localhost` 也可能按 `127.0.0.1` 匹配账号，两个都建最稳。
> `mysql_native_password` 是因为 MySQL 8 默认 `caching_sha2_password`，部分老驱动会握手失败；本项目驱动较新，用默认也行，但显式指定省心。

### 6.3 导入表结构与测试数据

先把 `sql/netguard.sql` 传到服务器（本机 PowerShell）：

```powershell
scp "D:\企业管理\sql\netguard.sql" root@1.2.3.4:/tmp/
```

服务器上导入（脚本自带 `CREATE DATABASE netguard` 与 `USE netguard`）：

```bash
mysql --default-character-set=utf8mb4 < /tmp/netguard.sql
```

校验：

```bash
mysql -e "USE netguard; SHOW TABLES; SELECT COUNT(*) AS devices FROM device; SELECT username,role FROM sys_user;"
```

应看到 9 张表、10 台设备、5 个账号（`admin` / `ops` / `ops_li` / `ops_wang` / `ops_zhao`）。

### 6.4 确认只监听本机

```bash
ss -lntp | grep 3306
# 期望：127.0.0.1:3306   不是 0.0.0.0:3306
```

如果是 `0.0.0.0`，编辑 `/etc/mysql/mysql.conf.d/mysqld.cnf`，加/改 `bind-address = 127.0.0.1`，然后 `systemctl restart mysql`。

### 6.5 时区

```bash
mysql -e "SELECT NOW();"
```

和 `date` 对比，差 8 小时说明 MySQL 用了 UTC。项目 JDBC URL 已带 `serverTimezone=Asia/Shanghai`，一般不用改；报表日期想更稳可以：

```bash
mysql -e "SET GLOBAL time_zone='+08:00';"
# 持久化：/etc/mysql/mysql.conf.d/mysqld.cnf 的 [mysqld] 段加 default-time-zone='+08:00'
```

## 八、第 6 步：配置文件与应用服务

### 6.1 环境变量文件

`application-prod.yml` 从环境变量取值，集中写在 `/opt/netguard/.env`：

```bash
cat > /opt/netguard/.env <<'EOF'
# ===== 数据库 =====
MYSQL_PASSWORD=换成你的强密码

# ===== 下面三项先按"极简模式"关掉 =====
# 服务器上没装 Redis / RabbitMQ / 邮件服务时关闭，功能自动降级，不影响页面使用
APP_CACHE_MODE=memory
APP_MQ_ENABLED=false
APP_MAIL_ENABLED=false

# ===== 只监听本机，由 Nginx 对外（方案 B 用；方案 A 请删掉这一行） =====
SERVER_ADDRESS=127.0.0.1
EOF

chown netguard:netguard /opt/netguard/.env
chmod 600 /opt/netguard/.env
```

极简模式的三个降级分别意味着：

| 关闭项 | 后果 | 影响 |
| --- | --- | --- |
| `APP_CACHE_MODE=memory` | 实时状态存内存，不连 Redis | 多实例时缓存不共享；单机无感 |
| `APP_MQ_ENABLED=false` | 告警通知改为线程池同步发送（`LocalAlarmEventPublisher`） | 页面通知照发，只是少了 MQ 削峰 |
| `APP_MAIL_ENABLED=false` | 不发邮件，`notify_record` 记为"已跳过" | 站内通知正常 |

想用满血版（Redis + RabbitMQ + 邮件）见第九节，装完把这三行改回 `redis / true / true`。

### 6.2 systemd 托管

```bash
cp /opt/netguard/deploy/netguard.service /etc/systemd/system/netguard.service
```

如果不想用仓库那份、想手写一遍（内容基本一致，另外显式加了 `-Duser.timezone=Asia/Shanghai`）：

```bash
cat > /etc/systemd/system/netguard.service <<'EOF'
[Unit]
Description=NetGuard 网络故障告警监控平台 (Spring Boot, prod)
After=network.target mysql.service
Wants=mysql.service

[Service]
Type=simple
User=netguard
Group=netguard
WorkingDirectory=/opt/netguard
EnvironmentFile=/opt/netguard/.env
ExecStart=/usr/bin/java -Xms512m -Xmx1024m -Dfile.encoding=UTF-8 -Duser.timezone=Asia/Shanghai -jar /opt/netguard/netguard.jar --spring.profiles.active=prod
SuccessExitStatus=143
Restart=always
RestartSec=10
StandardOutput=journal
StandardError=journal

[Install]
WantedBy=multi-user.target
EOF

systemctl daemon-reload
systemctl enable --now netguard
systemctl status netguard --no-pager | head -12
```

看日志：

```bash
journalctl -u netguard -f          # 实时
tail -f /opt/netguard/logs/netguard.log
```

### 6.3 自检

```bash
curl -I http://127.0.0.1:8080/login
# 期望：HTTP/1.1 200
```

到这一步，方案 A 已经可以用了：安全组放行 8080 → 浏览器打开 `http://1.2.3.4:8080` → `admin / admin123`。**先把默认密码改掉再给别人看。**

## 九、第 7 步：Nginx 反向代理（方案 B）

### 7.1 安装并写一个「先用 80 端口」的配置

```bash
apt install -y nginx
systemctl enable --now nginx
```

`/etc/nginx/sites-available/netguard`：

```nginx
server {
    listen 80;
    server_name _;              # 有域名就写域名，没有就保持 _

    client_max_body_size 10m;   # 允许上传设备图片（应用限制 5MB）

    location / {
        proxy_pass http://127.0.0.1:8080;
        proxy_http_version 1.1;
        proxy_set_header Host              $host;
        proxy_set_header X-Real-IP         $remote_addr;
        proxy_set_header X-Forwarded-For   $proxy_add_x_forwarded_for;
        proxy_set_header X-Forwarded-Proto $scheme;
        proxy_set_header Connection        "";
        proxy_read_timeout 60s;
    }

    # 上传的图片走应用（应用有静态资源映射），先保证能显示
    location ^~ /uploads/ {
        proxy_pass http://127.0.0.1:8080;
        proxy_set_header Host $host;
    }
}
```

启用：

```bash
ln -sf /etc/nginx/sites-available/netguard /etc/nginx/sites-enabled/netguard
rm -f /etc/nginx/sites-enabled/default
nginx -t && systemctl reload nginx
```

现在 `http://1.2.3.4` 就能打开。**此时记得回到 `.env` 确认 `SERVER_ADDRESS=127.0.0.1`，并从安全组删掉 8080 规则。**

### 7.2 用仓库里的加强版配置（二选一）

`deploy/nginx.conf` 是更完整的版本：gzip、静态资源缓存、`/nginx-health`、安全响应头、443 + HSTS 注释示例。要用它：

```bash
# 1) 上传 deploy/ 目录
scp -r "D:\企业管理\deploy" root@1.2.3.4:/opt/netguard/
# 2) 备份并替换
cp /etc/nginx/sites-available/netguard /etc/nginx/sites-available/netguard.bak
cp /opt/netguard/deploy/nginx.conf /etc/nginx/sites-available/netguard
# 3) 改 server_name 与证书路径（证书见第 8 节，拿到证书后再改 443 部分）
vim /etc/nginx/sites-available/netguard
nginx -t && systemctl reload nginx
```

## 十、第 8 步：域名 + HTTPS

### 8.1 域名解析

在你买域名的地方（阿里云/腾讯云/Cloudflare）加一条 A 记录：

| 主机记录 | 类型 | 值 |
| --- | --- | --- |
| `netguard`（或 `@`） | A | 服务器公网 IP |

验证（本机）：

```powershell
nslookup netguard.你的域名.com 8.8.8.8
```

返回服务器 IP 就生效了（通常几分钟，最长 24 小时）。

> **国内服务器**：域名要 ICP 备案，否则 80/443 会被服务商拦（表现是一直超时，不是 502）。没备案就先用香港/境外机器，或走方案 A 的 IP:8080。

### 8.2 申请免费证书

```bash
apt install -y certbot python3-certbot-nginx
# 注意用 certonly：只申请证书，不改我们的配置
certbot certonly --nginx -d netguard.你的域名.com
# 按提示填邮箱、同意条款、可选不接收邮件
ls /etc/letsencrypt/live/netguard.你的域名.com/
# fullchain.pem  privkey.pem
```

证书 90 天自动续期（certbot 装好了 systemd timer），检查：

```bash
systemctl list-timers | grep certbot
certbot renew --dry-run
```

### 8.3 改成 443 + HTTP 跳转

`/etc/nginx/sites-available/netguard`（把域名和证书路径换成自己的）：

```nginx
# HTTP 全部跳 HTTPS
server {
    listen 80;
    server_name netguard.你的域名.com;
    return 301 https://$host$request_uri;
}

server {
    listen 443 ssl;
    server_name netguard.你的域名.com;

    ssl_certificate     /etc/letsencrypt/live/netguard.你的域名.com/fullchain.pem;
    ssl_certificate_key /etc/letsencrypt/live/netguard.你的域名.com/privkey.pem;
    ssl_protocols TLSv1.2 TLSv1.3;
    ssl_session_cache shared:SSL:10m;

    client_max_body_size 10m;

    gzip on;
    gzip_min_length 1024;
    gzip_types text/plain text/css application/javascript application/json image/svg+xml;

    location / {
        proxy_pass http://127.0.0.1:8080;
        proxy_http_version 1.1;
        proxy_set_header Host              $host;
        proxy_set_header X-Real-IP         $remote_addr;
        proxy_set_header X-Forwarded-For   $proxy_add_x_forwarded_for;
        proxy_set_header X-Forwarded-Proto $scheme;
        proxy_set_header Connection        "";
        proxy_read_timeout 60s;
    }

    location ^~ /uploads/ {
        proxy_pass http://127.0.0.1:8080;
        proxy_set_header Host $host;
    }
}
```

```bash
nginx -t && systemctl reload nginx
curl -I https://netguard.你的域名.com/login
```

> **HTTP/2 写法看 Nginx 版本**：Ubuntu 22.04（Nginx 1.18）、24.04（1.24）要用 `listen 443 ssl http2;`；1.25.1 以后 `http2` 从 `listen` 参数改成独立指令 `http2 on;`，上面的 `listen 443 ssl;` 就是新版写法。`nginx -t` 报 `unknown directive "http2"` 就说明版本旧，把 `listen` 那行改成 `listen 443 ssl http2;` 即可。
>
> HTTPS 之后如果登录跳转出现 `http://` 混跳，检查 `X-Forwarded-Proto` 有没有传（上面配置已包含）；Spring Boot 2.7 在 `server.forward-headers-strategy` 默认 `native`，能识别这个头。

## 十二、第 10 步：上线必做的六件事

1. **改默认密码**：`admin`、`ops` 全部改掉（个人中心 → 修改密码），或直接删掉不用的账号：
   `mysql -e "USE netguard; UPDATE sys_user SET status=0 WHERE username IN ('ops_li','ops_wang','ops_zhao');"`
2. **数据库不暴露**：确认 `bind-address=127.0.0.1`，安全组不放 3306。
3. **应用不暴露**：`.env` 里 `SERVER_ADDRESS=127.0.0.1`，安全组删掉 8080。
4. **开 HTTPS**：登录密码是明文表单，HTTP 下等于公开。
5. **文件权限**：`.env` 600，jar 640，`/opt/netguard` 750，属主 `netguard`。
6. **备份**：`crontab -e`（用 root 或 netguard）：

```cron
# 每天 02:00 备份数据库，保留 14 天
0 2 * * * mysqldump -u netguard -p'你的密码' --single-transaction --default-character-set=utf8mb4 netguard | gzip > /opt/netguard/backup/db-$(date +\%F).sql.gz && find /opt/netguard/backup -name 'db-*.sql.gz' -mtime +14 -delete
# 每天 02:30 备份上传文件
30 2 * * * tar czf /opt/netguard/backup/uploads-$(date +\%F).tar.gz -C /opt/netguard uploads
```

恢复：

```bash
gunzip -c /opt/netguard/backup/db-2026-11-24.sql.gz | mysql --default-character-set=utf8mb4 netguard
```

## 十三、常见故障对照表

| 现象 | 大概率原因 | 处理 |
| --- | --- | --- |
| 浏览器一直转圈 / 超时 | 安全组没放行，或国内域名未备案 | 查安全组；用 IP:端口先验证；备案 |
| `502 Bad Gateway` | 应用没起来，或端口不是 8080 | `systemctl status netguard`；`journalctl -u netguard -n 80 --no-pager` |
| 502 且日志 `Communications link failure` | 数据库连不上 | 查 `.env` 密码与 MySQL 用户；`mysql -u netguard -p -h 127.0.0.1 netguard` |
| 502 且日志 `Access denied for user 'netguard'@'localhost'` | 只建了 `@'127.0.0.1'` 账号 | 按 6.2 两条都建 |
| 登录后 500，页面提示模板错误 | 上传的 jar 是旧包，模板与代码不匹配 | 重新打包上传，`deploy.sh deploy` |
| 页面没样式、图表空白 | Nginx 把 `/css`、`/js` 也拦了 | 配置里只有 `location /` 就行，别加多余规则 |
| 上传图片报 413 | `client_max_body_size` 太小 | 改成 `10m` 后 reload |
| 上传成功但图片 404 | `/uploads/` 没代理到应用 | 加 7.1 那段 `location ^~ /uploads/` |
| 告警时间差 8 小时 | 系统/MySQL/JVM 时区不一致 | `timedatectl`、MySQL `default-time-zone`、`-Duser.timezone=Asia/Shanghai` |
| 启动几秒后退出，日志 `OutOfMemoryError` | 内存不足 | 降 `-Xmx` 到 768m 或加 swap（见下） |
| 日志里一堆 Redis 连接失败 | 没装 Redis 但 `APP_CACHE_MODE` 还是 redis | `.env` 改 `memory` 后重启 |
| 日志里 RabbitMQ 连接被拒 | 没装 RabbitMQ 但 `APP_MQ_ENABLED=true` | `.env` 改 `false` 后重启 |
| `bind: address already in use` | 8080 被旧进程占着 | `ss -lntp \| grep 8080` → `kill 旧PID` |

### 加 swap（1G 内存机器必备）

```bash
fallocate -l 2G /swapfile
chmod 600 /swapfile
mkswap /swapfile
swapon /swapfile
echo '/swapfile none swap sw 0 0' >> /etc/fstab
free -h
```

## 十四、升级到"满血版"（可选）

课程答辩只要求能跑通，下面这些**不是必须**。想要完整演示 MQ 异步与邮件通知再装。

### 14.1 Redis（实时状态缓存）

```bash
apt install -y redis-server
sed -i 's/^bind 127.0.0.1.*/bind 127.0.0.1/' /etc/redis/redis.conf
systemctl enable --now redis-server
redis-cli ping        # PONG
```

`.env` 里 `APP_CACHE_MODE=redis`，重启应用。验证：

```bash
redis-cli HGETALL netguard:device:status | head
```

### 14.2 RabbitMQ（告警异步通知）

```bash
apt install -y rabbitmq-server
systemctl enable --now rabbitmq-server

# 建应用账号与虚拟主机
rabbitmqctl add_user netguard '换成你的密码'
rabbitmqctl add_vhost /
rabbitmqctl set_permissions -p / netguard ".*" ".*" ".*"
rabbitmq-plugins enable rabbitmq_management   # 可选：15672 管理台
```

`.env` 追加（`application-prod.yml` 读这些变量）：

```bash
RABBITMQ_HOST=127.0.0.1
RABBITMQ_PORT=5672
RABBITMQ_USER=netguard
RABBITMQ_PASSWORD=换成你的密码
APP_MQ_ENABLED=true
```

> 15672 管理台不要对公网开放，需要看就 `ssh -L 15672:127.0.0.1:15672 root@1.2.3.4` 本地转发。

### 14.3 邮件通知（QQ 邮箱示例）

1. QQ 邮箱 → 设置 → 账户 → 开启 SMTP 服务 → 生成**授权码**（不是登录密码）；
2. `.env`：

```bash
MAIL_HOST=smtp.qq.com
MAIL_PORT=465
MAIL_USERNAME=你的QQ号@qq.com
MAIL_PASSWORD=授权码
APP_MAIL_ENABLED=true
```

3. 把告警规则里的"邮件通知"打开、填收件人（`ops@你的域名` 换成本人邮箱），然后手动执行一次巡检制造离线，看通知中心是否出现"邮件 发送成功"。

## 十五、Docker 方式（知道有这回事即可）

不想手动装 JDK/MySQL，可以容器化：

```bash
docker run -d --name netguard-mysql -p 127.0.0.1:3306:3306 \
  -e MYSQL_ROOT_PASSWORD=root密码 -e MYSQL_DATABASE=netguard \
  -v /opt/netguard/mysql:/var/lib/mysql mysql:8.0

docker run -d --name netguard-app -p 127.0.0.1:8080:8080 \
  -e MYSQL_PASSWORD=root密码 -e APP_CACHE_MODE=memory \
  -e APP_MQ_ENABLED=false -e APP_MAIL_ENABLED=false \
  -v /opt/netguard/uploads:/opt/netguard/uploads \
  -v /opt/netguard/logs:/opt/netguard/logs \
  -v /tmp/netguard.jar:/opt/netguard/netguard.jar:ro \
  eclipse-temurin:17-jre java -Dfile.encoding=UTF-8 -jar /opt/netguard/netguard.jar --spring.profiles.active=prod
```

注意两点：容器里数据库地址要按容器网络改（`-e SPRING_DATASOURCE_URL=...`）；Nginx 仍在宿主机上反代 `127.0.0.1:8080`。

## 十七、一页总结

1. 买 2C2G Ubuntu 22.04，安全组放 22 + 80 + 443；
2. `apt install openjdk-17-jdk-headless mysql-server nginx`；
3. 建 `netguard` 库与数据库账号，导入 `sql/netguard.sql`；
4. 本机 `mvn package`，`scp` 上传 jar 到 `/opt/netguard/`；
5. 写 `/opt/netguard/.env`（密码 + 三个降级开关 + `SERVER_ADDRESS=127.0.0.1`）；
6. 装 `netguard.service`，`enable --now`，`curl 127.0.0.1:8080/login` 应 200；
7. Nginx 反代 `127.0.0.1:8080`，域名解析 + `certbot` 上 HTTPS；
8. 改默认密码、关 3306/8080 公网、配每日备份。

做完这 8 步，别人用手机在任意网络下打开 `https://你的域名` 就能看到登录页，`admin / 你改后的密码` 登录进去就是完整平台。
