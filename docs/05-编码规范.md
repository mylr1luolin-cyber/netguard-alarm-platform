### 2.2 类与接口补充规则

1. 实体类名与表名对应并保持单数：表 `device` → `Device`，表 `device_type` → `DeviceType`；不写 `Devices`、`DeviceEntity`。
2. 同一能力存在多实现时才抽接口，接口名描述能力而不是描述实现。本项目的 `mq.AlarmEventPublisher` 由 `RabbitAlarmEventPublisher` 与 `LocalAlarmEventPublisher` 两个实现通过 `@ConditionalOnProperty` 切换；其余 Service 不做"接口 + impl"的空壳拆分。
3. 局部内部类/匿名类仅用于配置回调（如 `MetaObjectHandler`），长度超过 20 行的逻辑必须提取为具名方法。

### 2.3 数据库命名

| 元素 | 规则 | 示例 |
| --- | --- | --- |
| 表名 | 小写单数、snake_case，系统表可加 `sys_` 前缀 | `sys_user`、`device_type`、`alarm_record`、`daily_stat` |
| 字段名 | 小写 snake_case，与 Java 字段 camelCase 自动映射 | `device_name` ↔ `deviceName`、`create_time` ↔ `createTime` |
| 主键 | 统一 `id BIGINT AUTO_INCREMENT` | — |
| 唯一索引 | `uk_` 前缀 + 字段名 | `uk_username`、`uk_type_code`、`uk_device_code`、`uk_stat_date` |
| 普通索引 | `idx_` 前缀 + 字段名 | `idx_ip_address`、`idx_status`、`idx_alarm_time` |
| 布尔/标志位 | `TINYINT` 存 0/1，字段名不加 `is_` | `core_flag`、`read_flag`、`status` |
| 时间字段 | `*_time`（DATETIME）、`*_date`（DATE） | `alarm_time`、`stat_date` |

Java 侧禁止用 `is_` 开头字段（Lombok 生成的 getter 与 MyBatis 映射都容易出错）；数据库标志位在 Java 中保留 `Integer`，对外展示用 `getXxx() == 1` 判断，需要布尔语义时提供 `isXxx()` 方法（如 `LoginUser.isEnabled()`）。

## 3. 分层职责与依赖方向

### 3.1 依赖方向

```
浏览器 / 模板
    ▲  Model / IPage / VO
controller ──► service ──► mapper ──► MySQL
    │             │  └──► cache / mq / mail / probe
    │             └──► security.SecurityUtils（仅取当前登录人）
    └──► dto / query / vo / common.Result
```

硬性规则：

1. 只允许 `controller → service → mapper`；**禁止 controller 直接依赖 Mapper**，当前工程中 controller 的构造注入只有 Service（`DeviceController` 注入 `DeviceService`、`DeviceTypeService`、`InspectService`）。
2. 跨 Service 调用允许（`InspectService → DeviceService / AlarmService / CacheService`），但禁止循环依赖；发现环时把公共逻辑下沉到第三个 Service。
3. `dto/vo/query` 不得反向依赖 `service/controller`；`entity` 不得依赖任何业务类。
4. Controller 不得出现 `@Transactional`、`SqlSession`、`LambdaQueryWrapper`；Service 不得出现 `Model`、`RedirectAttributes`、`HttpServletRequest`。
5. 页面渲染需要的数据由 Controller 放进 Model；Controller 只做"取数 + 放模型 + 选视图"，业务判断一律在 Service。

### 3.2 各层职责清单

| 层 | 必须做 | 禁止做 |
| --- | --- | --- |
| controller | `@Valid` 校验、`BindingResult` 分支、闪存消息、`redirect:` 视图名 | 拼 SQL、计算业务状态、发邮件、写缓存 |
| service | 业务校验、事务、抛 `BusinessException`、记录操作人日志、缓存维护 | 返回 `SysUser` 等含敏感字段的实体给页面、捕获异常后静默、拼 HTML |
| mapper | 单表 Wrapper、XML 动态 SQL、分页 | 在 SQL 里做权限判断、返回 `Map` 代替 VO |
| security | 登录用户加载、当前用户工具、登录成功回调 | 业务查询 |

### 3.3 敏感字段与实体出参

1. `entity.SysUser` 含 `password`（BCrypt 密文），**禁止**作为 Controller 返回值或 Model 属性直接交给模板；个人中心等页面应使用只含 `realName/email/phone/avatar/role` 的视图对象，或在放入 Model 前显式置空密码。
2. 其余实体不含敏感字段，可作为查询结果传递；但一旦页面需要"表字段 + 关联字段"，必须新增 VO（如 `DeviceVO`），不允许在实体上挂 `@TableField(exist=false)` 的展示字段。
3. JSON 接口对外只返回 `Result<T>`，`data` 内不得出现密码、会话标识、内部堆栈。

### 3.4 正确与错误写法对照

```java
// 正确：Controller 只做绑定、校验、调 Service、选视图
@PostMapping
public String create(@Valid @ModelAttribute("deviceForm") DeviceForm form, BindingResult binding,
                     @RequestParam(value = "imageFile", required = false) MultipartFile imageFile,
                     Model model, RedirectAttributes redirect) {
    if (binding.hasErrors()) {
        return redisplayForm(form, model, false);
    }
    deviceService.create(form, imageFile);
    redirect.addFlashAttribute("msg", "设备「" + form.getDeviceName() + "」已加入监控");
    redirect.addFlashAttribute("msgType", "success");
    return "redirect:/devices";
}
```

禁止在 Controller 中注入 `Mapper`、直接调用 `updateById`，也禁止 `d == null` 时静默 `return`（应抛 `BusinessException`）。

## 4. Entity / DTO / VO / Query 划分

| 类型 | 包 | 用途 | 本项目清单 |
| --- | --- | --- | --- |
| Entity | `entity` | 与表一一对应，MyBatis-Plus 注解 | `SysUser`、`DeviceType`、`Device`、`AlarmRecord`、`NotifyRecord`、`InspectLog`、`InspectDetail`、`AlarmRule`、`DailyStat` |
| DTO/Form | `dto` | 接收页面表单，承载 JSR-303 校验 | `DeviceForm`、`DeviceTypeForm`、`RuleForm`、`AlarmConfirmForm`、`ProfileForm`、`PasswordForm` |
| VO | `vo` | 页面/JSON 展示所需字段 | `DeviceVO`、`AlarmRecordVO`、`DashboardVO`、`CountItemVO`、`DeviceFaultRankVO` |
| Query | `query` | 列表筛选 + 分页参数 | `DeviceQuery`、`AlarmQuery`、`NotifyQuery` |

### 4.1 四条硬规则

1. **Entity 只映射表**：字段与列一一对应，审计字段用 `@TableField(fill = ...)`，主键用 `@TableId(type = IdType.AUTO)`；不写业务方法（`getStatusText()` 之类的展示逻辑放 VO 或枚举）。
2. **Form 只进不出**：表单对象可以带 `id` 用于编辑回显，但不作为 Service 返回类型；表单字段必须有中文 `message`，与 04 文档的校验表一致。
3. **VO 只出不进**：VO 不接收表单参数。列表 VO 允许继承实体补充关联字段（`DeviceVO extends Device`，配 `@EqualsAndHashCode(callSuper = true)`），但**禁止**以 `SysUser` 为基类。
4. **Query 负责分页截断**：`page` 从 1 开始、`size` 默认 10，`getCurrent()/getLimit()` 做边界收敛（`getLimit()` 上限 100），Controller 与 Service 不得各自再写一套截断逻辑。

### 4.2 参考实现

```java
/** 设备列表查询条件。 */
@Data
public class DeviceQuery {
    private Integer page = 1;
    private Integer size = 10;
    private String keyword;
    private Long typeId;
    private String status;
    private Integer coreFlag;
    private String sortField;
    private String sortOrder;

    public long getCurrent() { return page == null || page < 1 ? 1L : page.longValue(); }
    public long getLimit() { return size == null || size < 1 ? 10L : Math.min(size, 100); }
}
```

## 5. MyBatis-Plus 使用规范

### 5.1 查询方式选择

| 场景 | 写法 | 示例 |
| --- | --- | --- |
| 单表条件查询 | `Wrappers.<T>lambdaQuery()` | `sysUserMapper.selectOne(Wrappers.<SysUser>lambdaQuery().eq(SysUser::getUsername, username))` |
| 单表更新 | `LambdaUpdateWrapper` | 通知已读：`.set(NotifyRecord::getReadFlag, 1)` |
| 多表关联 / 聚合 / 动态排序 | XML + `<if>/<choose>` | `DeviceMapper.xml#selectDevicePage`、`AlarmRecordMapper.xml#selectAlarmPage` |
| 分页 | `new Page<>(query.getCurrent(), query.getLimit())` 返回 `IPage<T>` | 列表页统一 `page.records` / `page.total` |

### 5.2 强制规则

1. **必须使用 `#{}`，禁止 `${}`**。参数一律预编译绑定；`${}` 只允许出现在不可能由用户控制的字面量位置，且评审时必须说明理由。当前工程 XML 中不存在 `${}`。
2. **模糊查询写 `CONCAT`**：`d.device_name LIKE CONCAT('%', #{q.keyword}, '%')`；禁止 `'%${keyword}%'`，也禁止用 `||` 拼接（MySQL 下 `||` 是逻辑或）。
3. **排序字段白名单**：`sortField` 来自请求参数，必须用 `<choose>` 映射为固定列名；禁止 `ORDER BY ${sortField}`，也禁止把 `asc/desc` 直接拼进 SQL（本项目在 `<when>` 内用 `<otherwise>DESC</otherwise>` 收敛方向）。
4. **分页统一 `page` / `size`**：Controller 接收同名参数，Query 收敛上限，MyBatis-Plus 分页拦截器再设 `maxLimit(200)` 兜底；禁止手写 `LIMIT` 做业务分页（`latestLog()` 取一条用 `Page(1,1)` 优先，历史代码的 `.last("LIMIT 1")` 仅限固定常量）。
5. **批量写入必须在事务内**：`@Transactional(rollbackFor = Exception.class)`，JDBC URL 已开 `rewriteBatchedStatements=true`；单批超过 100 条时改用 XML `<foreach>` 批量 INSERT，禁止在循环里逐条提交。
6. **审计字段自动填充**：`create_time/update_time` 由 `MybatisPlusConfig` 的 `MetaObjectHandler` 填充，业务代码不得手工 `setCreateTime(LocalDateTime.now())`。
7. **枚举映射**：实体字段直接用枚举类型，依赖 `default-enum-type-handler: EnumTypeHandler` 按名称落库（如 `status='ONLINE'`），禁止在 SQL 里写魔法字符串比较之外的转换逻辑。
8. **禁止全表 `selectList(null)` 扫大表**：`device` 等配置表可接受，`alarm_record`、`inspect_detail` 必须带条件或分页。

### 5.3 XML 写法示例

```xml
<!-- 正确：动态条件 + #{} + CONCAT + 排序白名单 -->
<select id="selectDevicePage" resultType="com.netguard.vo.DeviceVO">
    SELECT d.id, d.device_code, d.device_name, d.ip_address, t.type_name AS typeName
    FROM device d LEFT JOIN device_type t ON d.device_type_id = t.id
    <where>
        <if test="q.keyword != null and q.keyword != ''">
            AND d.device_name LIKE CONCAT('%', #{q.keyword}, '%')
        </if>
        <if test="q.status != null and q.status != ''">AND d.status = #{q.status}</if>
    </where>
    <choose>
        <when test="q.sortField eq 'device_name'">ORDER BY d.device_name ASC</when>
        <otherwise>ORDER BY d.id ASC</otherwise>
    </choose>
</select>
```

禁止写法 `LIKE '%${keyword}%'` 与 `ORDER BY ${sortField}`：`${}` 会直接替换进 SQL，用户输入即可注入。

## 6. 注释规范

### 6.1 注释层次

| 层次 | 要求 | 示例位置 |
| --- | --- | --- |
| 类头 | 每个类、枚举、接口必须有 Javadoc：一句话职责 + 关键流程/约束 | `InspectService` 顶部用 `<ol>` 写巡检查步骤 |
| 方法 | public 方法必须有 Javadoc，说明做什么、参数含义、返回值、异常；private 方法逻辑复杂时也写 | `InspectService.runInspect`、`AlarmService.createOfflineAlarm` |
| 字段/常量 | 实体字段、枚举常量、配置项用 `/** */` 单行说明 | `Result.timestamp`、`DeviceStatusEnum.ONLINE` |
| 行内 | 只解释"为什么"，不解释"是什么"；复杂条件、魔法值、降级分支必须写 | `offlineCount == threshold` 的幂等说明 |
| XML/配置 | 复杂 SQL 上方写一句用途；降级开关写清触发条件 | `DeviceMapper.xml` 的注释、`application-dev.yml` 的降级说明 |

### 6.2 类头模板

```java
/**
 * 巡检服务：对全部设备执行 TCP/ICMP 探测，记录批次与明细，并根据状态变化产生告警。
 *
 * <p>一次巡检的工作流程：
 * <ol>
 *   <li>读取当前告警规则（间隔、失败阈值、超时时间）；</li>
 *   <li>遍历设备，优先探测配置的监控端口（TCP），未配置端口时退回 ICMP；</li>
 *   <li>把探测结果写入 {@code inspect_detail}，状态写入 {@code device} 与缓存；</li>
 *   <li>连续失败达到阈值时生成离线告警，设备恢复在线时生成恢复通知。</li>
 * </ol>
 */
```

统一使用中文 Javadoc，`{@code 表名}` 标注表与键；不写 `@author`（避免多人反复改署名），需要追溯时看 Git 记录。

### 6.3 注释率 ≥15% 的统计口径

- 口径：`注释行数 ÷（有效代码行数 + 注释行数）`，百分比保留整数。
- 计入注释：`//` 行、`/* */`/`/** */` 块（含 Javadoc）、XML `<!-- -->`、YAML `#`、模板 `<!-- -->`、行尾注释。
- 不计入：空行、纯 `import`/`package` 行、纯括号行、`@Override` 等单行注解。
- 抽查方式：IDEA `Statistic` 插件按包统计，每月与提测前各一次；整体与单包均不低于 15%。
- 达成方式：类头 Javadoc（每个类 ≥3 行）+ public 方法 Javadoc（≥2 行）+ 实体/枚举字段注释 + 复杂 SQL 与降级逻辑行内注释；不靠堆砌无意义注释凑数。

## 7. 异常处理

### 7.1 异常分层

| 场景 | 处理方式 | 返回 |
| --- | --- | --- |
| 表单字段非法 | JSR-303 注解 + `@Valid`，Controller 检查 `BindingResult` 回填页面 | 原页面 + 逐字段错误 |
| 业务规则失败（重名、不存在、重复确认） | `throw new BusinessException(ResultCode.XXX)` 或 `BusinessException(code, "文案")` | `GlobalExceptionHandler` 统一处理 |
| 无权限 | `AccessDeniedException`（URL 规则）/ 主动抛 `BusinessException(ResultCode.FORBIDDEN, ...)` | 页面 `error/403`，AJAX `Result.fail` |
| 文件上传失败 | `BusinessException(ResultCode.FILE_UPLOAD_ERROR, "图片保存失败，请稍后重试")` | 同上 |
| 未预期异常 | 不捕获，由 `GlobalExceptionHandler` 兜底 `log.error` + 页面 `error/500` | 友好文案，不暴露堆栈 |

### 7.2 使用约定

1. 业务失败只抛 `BusinessException`，不抛 `RuntimeException`、不返回 `null` 让上层猜；错误码优先复用 `ResultCode` 既有枚举（1001–5002 分段见 `ResultCode`）。
2. **禁止吞异常**：`catch` 后必须"处理 + 记录 + 继续/转换"三者之一；禁止空 `catch`、禁止 `e.printStackTrace()`、禁止只 `printStackTrace` 不记日志。
3. 捕获后如需继续流程，用 `log.warn` 记录并返回安全默认值；如无法继续，包装为 `BusinessException` 抛出并保留 `cause`。
4. 事务方法统一 `@Transactional(rollbackFor = Exception.class)`；`BusinessException` 会触发回滚，事务内不得捕获业务异常后继续写库。
5. Controller 不得写 `try { ... } catch (Exception e) { return "error/500"; }`；页面跳转与错误视图交给全局处理器。
6. 异常文案面向用户，写清"发生了什么 + 怎么处理"，不带类名、SQL、堆栈。

```java
// 正确：业务校验失败抛 BusinessException，交给全局处理器
SysUser user = getById(userId);
if (!passwordEncoder.matches(form.getOldPassword(), user.getPassword())) {
    throw new BusinessException("原密码不正确");
}

// 正确：可降级链路捕获后记录并继续
try {
    sysUserMapper.updateById(update);
} catch (Exception e) {
    // 登录时间更新失败不影响登录本身
    log.warn("更新最近登录时间失败：{}", e.getMessage());
}
```

### 7.3 日志级别约定

| 级别 | 使用场景 | 本项目示例 |
| --- | --- | --- |
| `error` | 需人工介入的失败、未预期异常、外部依赖发送失败 | `GlobalExceptionHandler` 兜底异常；邮件发送异常 |
| `warn` | 业务规则拦截、降级、可恢复失败、敏感操作 | `BusinessException`、删除设备、巡检重入跳过、邮件通道未启用 |
| `info` | 关键业务动作完成 | 登录成功、设备增删改、巡检完成、告警产生/确认/恢复、规则变更 |
| `debug` | 排查细节，默认不在生产输出 | 全局角标加载失败、缓存重试细节 |

级别以 `logging.level.com.netguard` 控制：dev 为 `debug`，prod 为 `info`，root 分别为 `info`/`warn`。

## 8. 日志规范

### 8.1 格式与落地

- 日志格式（`logback-spring.xml`）：`%d{yyyy-MM-dd HH:mm:ss.SSS} [%thread] %-5level %logger{40} - %msg%n`，UTF-8。
- 输出：控制台 + `logs/netguard.log`（按天 + 20MB 滚动，保留 30 天，总上限 500MB）+ `logs/netguard-error.log`（仅 ERROR）。
- 打印方式：`@Slf4j` + 占位符 `log.info("巡检完成：批次 {}，共 {} 台", logEntity.getId(), devices.size())`；禁止字符串 `+` 拼接，禁止 `System.out.println`。

### 8.2 必须记录的字段

| 操作 | 必含信息 | 示例 |
| --- | --- | --- |
| 登录成功/失败 | 账号、角色/来源 IP（失败时） | `用户 [admin] 登录成功，角色 ADMIN` |
| 设备增删改 | 操作人、设备编号/名称 | `用户 admin 创建设备 DEV-CORE-01` |
| 巡检 | 批次号、总数、在线/离线数、耗时 | `巡检完成：批次 12，共 8 台，在线 6，离线 2，耗时 1520 ms` |
| 告警 | 告警 ID、设备、级别、状态变化 | `产生离线告警：设备 CoreSW-01（10.10.1.1），级别 URGENT` |
| 规则变更 | 操作人、变更前后关键值 | `告警规则已更新：间隔 5→10 分钟，阈值 2 次` |
| 邮件发送 | 主题、收件人（脱敏）、结果 | `告警邮件发送成功，收件人=[a***@netguard.com]，主题=【紧急】设备离线告警` |
| 降级 | 触发原因与恢复动作 | `Redis 不可用，已自动降级为本地内存缓存` |

### 8.3 禁止与脱敏

1. **禁止打印**：明文/密文密码、`_csrf` token、`JSESSIONID`、完整邮箱、完整手机号、身份证、SQL 参数中的上述内容。
2. 邮箱脱敏：本地部分保留首字母 + `***`，域名完整保留（`zhangsan@netguard.com` → `z***@netguard.com`）；手机号保留前 3 后 4（`138****0001`）。
3. 关键操作必须带操作人：Controller/Service 通过 `SecurityUtils.currentUsername()` 或方法参数 `operator` 获取，自动任务统一为 `system`。
4. 不在循环内打印大对象；集合只打印数量或 ID 列表。
5. `log.error` 必须带异常对象（`log.error("保存失败", e)`），保留堆栈；同一异常只记一次，避免"catch 里 log + 全局再 log"重复刷屏。

```java
// 正确：占位符 + 操作人 + 不含敏感信息
log.info("用户 {} 修改了登录密码", user.getUsername());
log.warn("邮箱 {} 发送失败：{}", maskEmail(address), e.getMessage());

// 错误：完整邮箱 + 密码 + 字符串拼接
log.info("mail to " + email + " pwd=" + password);
```

> 邮箱脱敏为日志侧规则，打印前按上述规则处理即可；改造范围以 `MailService`、`NotifyService` 的收件人日志为准。

## 9. 时间、数值与金额

### 9.1 时间

| 场景 | 类型/格式 | 说明 |
| --- | --- | --- |
| 数据库 DATETIME/DATE | `LocalDateTime` / `LocalDate` | 实体字段、Mapper 参数统一使用 Java 8 时间类型 |
| JSON 输出 | `yyyy-MM-dd HH:mm:ss` | `JacksonConfig` 全局注册 `LocalDateTime/LocalDate/LocalTime` 序列化器 |
| 页面展示 | `#temporals.format(time, 'yyyy-MM-dd HH:mm:ss')` | 依赖 `thymeleaf-extras-java8time`，禁止在模板里调 `toString()` |
| 接口接收日期参数 | `yyyy-MM-dd`（`startDate`/`endDate`） | 与 04 文档一致 |
| 时区 | `Asia/Shanghai`（GMT+8） | JDBC URL `serverTimezone=Asia/Shanghai`，`spring.jackson.time-zone=GMT+8`，服务器/容器同步设置 |
| 时长展示 | `DurationUtils` 统一格式化 | 存储用整数分钟 `duration_minutes`、毫秒 `cost_ms`/`latency_ms` |

约定：禁止 `java.util.Date`、`Calendar`、`SimpleDateFormat`（线程不安全）；时间比较用 `isBefore/isAfter`；跨天统计用 `LocalDate.atStartOfDay()` 取边界，如 `DailyStatJob.statDate`。

### 9.2 数值

| 数据 | 类型 | 说明 |
| --- | --- | --- |
| 主键/外键、计数 | `Long` | 实体 `Long id`，统计返回值 `long`，Mapper 返回 `Long` 时判空 |
| 端口、阈值、超时 | `Integer` / `int` | 校验范围见 04 文档（端口 1–65535、阈值 1–5、超时 500–10000ms） |
| 耗时 | `int`（毫秒）/ `long`（批次耗时） | 展示时换算为秒 |
| 占比、平均 | `double`（仅展示） | 计算后可四舍五入到 1 位小数；禁止用 `float` 累加 |
| 金额 | 本项目无金额字段 | 后续若扩展计费，统一 `BigDecimal` + `DECIMAL(12,2)`，禁止 `double` |

## 10. 前端规范

### 10.1 模板复用

1. 每个页面固定四段片段，禁止复制侧边栏/顶栏 HTML：

```html
<head th:replace="~{fragments/layout :: head('设备管理')}"></head>
<body>
<aside th:replace="~{fragments/layout :: sidebar('devices')}"></aside>
<div class="main">
    <header th:replace="~{fragments/layout :: topbar('设备管理', '维护需要监控的网络设备及其类型、端口与重点标记')}"></header>
    <div class="flash-wrap" th:replace="~{fragments/layout :: flash}"></div>
    <div class="content"><!-- 页面内容 --></div>
</div>
</body>
```

2. `sidebar(activeKey)` 只允许 `dashboard/devices/inspects/alarms/statistics/notices/types/rule/profile`，新增菜单必须同步该取值与 04 文档页面清单。
3. 页面脚本统一在 `</body>` 前引入 `app.js`；图表页再引入 `echarts.min.js` 与页面脚本，禁止 CDN 外链（答辩论据：断网可演示）。
4. 权限按钮用 `sec:authorize="hasRole('ADMIN')"`；隐藏按钮只是体验优化，服务端仍必须由 URL 规则拦截（见 06 文档）。

### 10.2 Thymeleaf 三条铁律

1. **一个属性只写一个 `${}`**：三元与格式化都放进同一个表达式。正确 `${d.lastCheckTime != null ? #temporals.format(d.lastCheckTime,'yyyy-MM-dd HH:mm:ss') : '—'}`；错误 `th:text="${d.lastCheckTime != null} ? ${...} : '—'"`（会原样输出）。
2. **条件与取值都写变量名**，不在三元里嵌套 `${}`；动态表单地址先 `th:with` 算好再 `th:action="@{${formAction}}"`。
3. **用户输入一律 `th:text`**（默认 HTML 转义），全项目禁止 `th:utext`；内联脚本用 `th:inline="javascript"` 由 Thymeleaf 序列化。

### 10.3 JS 与 CSS

- 不引入 Vue/React、jQuery、Bootstrap 或任何前端构建工具；只允许原生 JS 与 Thymeleaf 服务端渲染，ECharts 以本地静态文件引入。
- 公共脚本写成 IIFE + `'use strict'`（参考 `app.js`），事件统一用 `addEventListener` 委托；**禁止在 HTML 里写 `onclick="..."` 业务逻辑**，页面级初始化脚本只做图表渲染与表单增强，超过 30 行提取到 `static/js/` 下的同名脚本。
- 样式只写 `static/css/style.css`：颜色、圆角、阴影用 `:root` 变量；类名采用"块 + 元素"短横线（BEM-ish）：块 `.card`、元素 `.card-head`/`.cell-main`，状态类加前缀（`.badge.b-online`、`.b-urgent`），布局工具类 `.spacer`/`.right`/`.gap-8`；禁止行内 `style` 控制布局（进度条等动态宽度允许 `th:style`）。
- 表单：`th:action` 自动附加 CSRF 隐藏域，禁止手写 `action`；校验错误用 `#fields.hasErrors('field')` 逐字段回显；危险操作加 `data-confirm`，由 `app.js` 统一二次确认。
- 分页链接必须带全查询条件（`page`、`size`、`keyword`、`typeId`、`status` 等），筛选条固定 `.filter-bar`，重置指向不带参数的当前路径。
- 空列表渲染 `.empty`（图标 + 说明），不显示空表格；按钮文案用动词（"保存规则"而不是"提交"）。

## 11. Git 提交规范

### 11.1 仓库初始化与忽略

当前项目尚未初始化 Git，首次提交前依次执行 `git init`、`git add .`、`git commit -m "chore: 初始化 NetGuard 工程"`。

`.gitignore` 必须包含：`target/`、`logs/`、`uploads/`、`.idea/`、`*.iml`、`*.log`、`start-dev.bat` 之外的本机脚本与临时文件。分支：`main` 保持可构建，功能开发用 `feature/模块名`，修复用 `fix/问题简述`。

### 11.2 提交信息格式

```
<type>(<scope>): <subject>
```

| type | 含义 | 示例 |
| --- | --- | --- |
| `feat` | 新功能 | `feat(device): 设备列表支持按离线次数排序` |
| `fix` | 修复缺陷 | `fix(alarm): 修复重复确认未拦截的问题` |
| `docs` | 文档 | `docs(05): 补充 MyBatis 排序白名单说明` |
| `style` | 格式/样式（不改逻辑） | `style(css): 统一表格行高与徽标间距` |
| `refactor` | 重构 | `refactor(inspect): 抽取巡检告警判定方法` |
| `test` | 测试 | `test(alarm): 增加恢复闭环用例` |
| `chore` | 构建/依赖/脚本 | `chore(deps): 升级 mybatis-plus 至 3.5.5` |

规则：subject 用中文、动词开头、不超过 50 字、句末不加句号；一次提交只做一件事；提交前必须 `mvn -B -DskipTests package` 通过；开发日志与代码同一次提交，message 形如 `docs(log): 2026-11-24 开发日志`。

```
feat(inspect): 手动巡检生成批次与明细
fix(security): 登录失败提示统一为“账号或密码错误”
docs(log): 2026-11-24 开发日志
```

## 12. 代码评审 checklist

提交评审前逐项自检，评审人按同一清单逐条勾选：

- [ ] 命名符合第 2 节：类/方法/变量/常量/表字段命名无拼音、无 `tmp`、无单字母
- [ ] 分层正确：Controller 无 Mapper 注入、无 SQL、无事务；Service 无 `Model`/`HttpServletRequest`
- [ ] 实体未直接暴露给模板，`SysUser.password` 未进入 Model 或 JSON
- [ ] 表单对象带 JSR-303 中文提示，Controller 有 `@Valid` + `BindingResult` 分支
- [ ] 分页使用 `page/size` 与 Query 的 `getCurrent()/getLimit()`，未手写 LIMIT
- [ ] SQL 全部 `#{}`，模糊查询用 `CONCAT`，排序字段走白名单
- [ ] 写操作只有 POST，表单用 `th:action`，无 GET 副作用
- [ ] 业务失败抛 `BusinessException`，无空 catch、无 `printStackTrace`
- [ ] 类头/公共方法 Javadoc 完整，复杂逻辑有"为什么"注释，注释率抽检 ≥15%
- [ ] 日志含操作人、无密码/完整邮箱，级别使用符合第 7.3 节
- [ ] 时间统一 `LocalDateTime` + `yyyy-MM-dd HH:mm:ss`，无 `Date`/`SimpleDateFormat`
- [ ] 页面无 `th:utext`、无内联 `onclick`、无外部 CDN，片段复用 `layout.html`
- [ ] commit message 符合第 11 节，构建通过，开发日志已更新
