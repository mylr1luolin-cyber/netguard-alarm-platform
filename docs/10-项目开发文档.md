# 10 项目开发文档（交付说明）

> 项目名称：NetGuard 网络故障告警监控平台（期末综合大作业·题目七）
> 版本：v1.0.0　交付日期：2026-11-24　技术栈：Spring Boot 2.7.18 + Thymeleaf + MyBatis-Plus + MySQL 8 + Redis + RabbitMQ + Spring Security

---

## 一、项目概述

NetGuard 面向企业网络运维场景，解决"设备多、故障发现慢、通知靠人喊、故障无记录"的问题：

1. **设备台账**：统一维护设备名称、IP、类型、监控端口、位置、是否重点监控，支持图片与备注；
2. **自动巡检**：按可配置间隔（5/10/30 分钟）对全部设备做 TCP 端口或 ICMP Ping 探测，结果入库并在缓存中维护实时状态；
3. **故障告警**：连续失败达到阈值即判定离线并生成告警，按"是否重点设备"区分紧急/普通，异步推送页面与邮件通知；
4. **处理闭环**：运维人员确认告警并填写处理情况，设备恢复在线时自动发送恢复通知并回填故障持续时长；
5. **统计分析**：告警历史多条件查询、设备故障次数排行、月度趋势与级别分布图表；
6. **规则配置**：巡检间隔、失败阈值、超时时间、通知渠道开关集中配置，保存后即时生效，无需重启。

角色划分：**ADMIN**（设备增删改、类型管理、规则配置、查看与处理全部告警）、**OPS**（查看设备状态与告警、确认告警、手动触发巡检）。

## 六、技术亮点与难点

1. **动态巡检调度**：`@Scheduled` 无法运行时改间隔，改用 `ThreadPoolTaskScheduler` 自持 `ScheduledFuture`，配合 `RuleChangedEvent` 实现配置即生效；`AtomicBoolean` 防重入避免批次叠加。
2. **可降级的中间件依赖**：缓存（Redis → 内存，60 秒自动重连）、消息（RabbitMQ → 本地同步）、邮件（开关关闭记 `SKIPPED`），使项目在无中间件的单机环境仍可完整演示，同时生产配置不改代码即可启用。
3. **告警精度控制**：连续失败阈值 + `==` 判定，避免网络抖动误报与告警风暴；恢复时回填 `duration_minutes`，为"平均处理时长"指标提供数据。
4. **闭环设计**：告警产生（PENDING）→ 确认（CONFIRMED，记录处理人/时间/说明）→ 恢复（RECOVERED）三段状态与页面时间线一一对应。
5. **查询与性能**：列表页分页 + 动态 SQL 白名单排序；看板聚合结果缓存 30 秒；趋势图按日期分组并在服务端补齐缺失日期。
6. **安全**：BCrypt、CSRF、URL 级 + 页面级双重鉴权、上传白名单与 UUID 重命名、全局异常不泄露堆栈、MyBatis 全 `#{}`。

## 七、运行与演示

```powershell
# 1. 初始化数据库（MySQL 8，root/123456）
mysql -u root -p123456 --default-character-set=utf8mb4 < sql\netguard.sql

# 2. 构建
$env:JAVA_HOME='D:\devtools\jdk17\jdk-17.0.2'; $env:MAVEN_OPTS='-Dfile.encoding=UTF-8'
mvn -B -DskipTests package

# 3. 启动（dev：MQ 与邮件关闭，Redis 缺失自动降级）
java -jar target\netguard.jar --spring.profiles.active=dev
# 或双击 start-dev.bat
```

访问 `http://localhost:8080`，演示账号 `admin/admin123`、`ops/ops123`。

**答辩演示脚本（5 分钟）**

1. 用 admin 登录 → 看板：指标卡、趋势、状态/类型分布、故障排行；
2. 设备页：按"离线"筛选 → 展示离线设备 → 点"立即探测"观察状态变化；
3. 立即执行一次巡检 → 批次详情看逐台探测结果与耗时；
4. 制造离线：把某台设备端口改成未监听值 → 保存 → 巡检两次触发告警（紧急/普通）→ 通知中心出现未读；
5. 打开告警详情 → 填写处理说明并确认 → 时间线推进 → 恢复设备后再次巡检，观察自动恢复通知与持续时长；
6. 规则页：把间隔从 5 分钟改为 30 分钟保存 → 说明调度已热更新；
7. 用 ops 账号登录 → 访问"设备类型"得到 403，验证权限隔离；
8. 统计报表：时间范围查询、故障排行、月度图表。

## 八、遗留问题与改进方向

1. 探测串行执行，200 台以上设备时单批次耗时会超过 1 分钟，后续改为受限并发；
2. 多实例部署时定时任务会重复执行，需引入 Redis 分布式锁；
3. 通知渠道仅页面与邮件，枚举已预留扩展点，可加短信/企业微信；
4. 统计报表暂不支持导出，可加 EasyExcel 导出；
5. 单元测试与集成测试覆盖不足，建议补充到 60% 以上。
