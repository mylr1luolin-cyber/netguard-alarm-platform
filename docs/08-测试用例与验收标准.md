# 08 测试用例与验收标准

> 被测系统：NetGuard 网络故障告警监控平台（`com.netguard`）
> 测试环境：Windows + JDK 17 + MySQL 8.0.28（127.0.0.1:3306/netguard）+ `spring.profiles.active=dev`
> 文档版本：v1.0　编写日期：2026-11-24

## 1. 测试环境与准备

| 项 | 值 |
| --- | --- |
| 应用地址 | http://localhost:8080 |
| 启动命令 | `java -jar target/netguard.jar --spring.profiles.active=dev`（或双击 `start-dev.bat`） |
| 数据库 | `netguard`，账号 root/123456，已导入 `sql/netguard.sql` |
| 缓存 | Redis 未启动时自动降级为内存缓存（日志出现 `Redis 不可用，已降级为内存缓存`） |
| 消息队列 | dev 环境 `app.mq.enabled=false`，走本地同步通知 |
| 邮件 | dev 环境 `app.mail.enabled=false`，通知记录状态为 `SKIPPED` |
| 账号 | `admin/admin123`（ADMIN）、`ops/ops123`（OPS）、`ops_zhao/ops123`（禁用） |

**测试数据要点**：10 台设备覆盖在线/离线/未知三种状态；14 条告警覆盖 `PENDING`/`CONFIRMED`/`RECOVERED`；6 个巡检批次、16 条明细；1 条启用规则（间隔 5 分钟、阈值 2、超时 2000 ms、紧急告警开启、页面通知开启、邮件关闭）。

## 4. 巡检与告警链路测试

| 编号 | 前置 | 步骤 | 预期结果 |
| --- | --- | --- | --- |
| TC-INSP-01 | admin 已登录 | 点击"立即巡检" | 生成新批次并跳转详情页，显示总数/在线/离线/耗时与逐台明细 |
| TC-INSP-02 | 存在离线设备 | 查看批次明细 | 离线设备明细 `result=FAILED`，`message` 为探测失败原因（如 `Connect timed out`） |
| TC-INSP-03 | 规则阈值=2 | 让某在线设备连续 2 次探测失败 | 第 2 次失败时创建 1 条 `OFFLINE` 告警，`alarm_level` 按是否重点设备取 `URGENT`/`NORMAL` |
| TC-INSP-04 | 同上，继续第 3 次失败 | 不再新增告警（阈值用 `==` 判定），`offline_count` 继续累加 |
| TC-INSP-05 | 存在 `PENDING` 离线告警 | 该设备恢复在线并巡检一次 | 原告警置 `RECOVERED` 并写入 `recover_time`、`duration_minutes`；新增 1 条 `RECOVER` 恢复通知记录 |
| TC-INSP-06 | 设备恢复后再次离线至阈值 | 检查告警列表 | 产生新的 `PENDING` 告警（历史已恢复告警不重复使用） |
| TC-INSP-07 | 告警已产生 | 查看 `/notices` | 出现 1 条 `PAGE` 通道通知，标题带【紧急】或【普通】前缀，未读红点 +1 |
| TC-INSP-08 | 告警已产生 | 检查 `alarm_record.notify_sent` | 通知成功后被置为 1 |
| TC-INSP-09 | dev 环境（邮件关闭） | 检查 `notify_record` 的 MAIL 行 | `status=SKIPPED`，`error_msg` 说明未配置/未开启邮件通道 |
| TC-INSP-10 | 规则页把间隔改为 30 分钟并保存 | 观察日志与下次巡检 | 调度按新间隔重排（`RuleChangedEvent` 生效），无需重启应用 |
| TC-INSP-11 | 规则页暂停巡检（`active_flag=0`） | 等待原间隔时间 | 不再自动巡检，手动巡检仍可用 |
| TC-INSP-12 | 自动巡检运行中 | 再点"立即巡检" | 手动批次正常执行，未出现并发的重复批次串号（`running` 标志防重入） |

## 9. 验收标准（逐项打勾）

| # | 验收项 | 判定方式 | 结果 |
| --- | --- | --- | --- |
| 1 | 项目可用 Maven 标准构建、可运行 | `mvn -B -DskipTests package` 成功，`java -jar` 启动无异常 | ☑ |

| 4 | 定时巡检按配置间隔执行，结果入库并在缓存中可查实时状态 | TC-INSP-01 ~ 03、看板设备状态 | ☑ |

| 7 | 告警可确认并记录处理情况 | TC-ALM-03 ~ 04 | ☑ |
| 8 | 恢复在线自动发恢复通知并闭环原告警 | TC-INSP-05 | ☑ |

## 10. 缺陷记录与回归

| 缺陷编号 | 涉及用例 | 现象 | 原因 | 修复 | 状态 |
| --- | --- | --- | --- | --- | --- |
| BUG-01 | TC-INSP-03 | 一次故障产生多条重复告警 | 阈值判断误用 `>=` | 改为 `== failThreshold` | 已修复 |
| BUG-02 | TC-ALM-04 | 重复确认覆盖确认人 | 确认前未校验状态 | 非 `PENDING` 直接抛业务异常 | 已修复 |
| BUG-03 | TC-NOT-01 | 未读数与列表不一致 | 计数含已读旧数据 | 统一按 `read_flag=0` 统计 | 已修复 |
| BUG-04 | TC-DASH-06 | 无设备时看板 500 | 在线率除零 | 分母为 0 时返回 0 | 已修复 |

> 回归策略：每个缺陷修复后至少重跑所属模块全部用例 + 看板用例（TC-DASH-01），确认无副作用。
