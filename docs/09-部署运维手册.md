# 09 部署运维手册
> 文档版本：v1.0　编写日期：2026-11-24　适用代码：`com.netguard`（Spring Boot 2.7.18）
> 构建产物：`target/netguard.jar`　默认端口：8080　生产 profile：`prod`

**验证范围**：第四章 Windows 环境是本项目**实际构建并运行验证**的环境（JDK 17.0.2 + MySQL 8.0.28）；Linux / Nginx / systemd 部分为课程要求的标准化生产方案，未在真实 Linux 服务器验证，上线前须按 `nginx -t`、`systemctl status`、健康检查逐项核对。

## 环境要求
| 组件 | 推荐版本 | 用途 | 最低配置 / 说明 |
| --- | --- | --- | --- |
| 操作系统 | CentOS 7.9+ / Rocky 8+ / Ubuntu 20.04+ | 运行环境 | 2 核 4GB、20GB 系统盘，单机部署即可 |

                     浏览器 / 运维终端
                            │ HTTPS 443（生产）
                            ▼
              ┌──────────────────────────────┐
              │  Nginx                       │
              │  · TLS 1.2/1.3 终止          │
              │  · / → 反代 127.0.0.1:8080   │
              │  · /uploads/ → alias 直读    │
              └──────────────┬───────────────┘
                             │ HTTP（仅回环）
                             ▼
     ┌────────────────────────────────────────────────┐
     │  Spring Boot 2.7.18  netguard.jar（prod）      │
     │  :8080 内嵌 Tomcat + Thymeleaf + Security      │
     │  · 动态巡检（ThreadPoolTaskScheduler）          │
     │  · 告警落库 → MQ 通知 → 邮件                    │
     └───┬──────────────┬──────────────┬──────────────┘
         │              │              │
         ▼              ▼              ▼
  ┌────────────┐  ┌───────────┐  ┌──────────────┐
  │ MySQL 8.0  │  │  Redis    │  │  RabbitMQ 3.x│
  │ netguard   │  │ 失败→内存 │  │ 失败→本地同步│
  │ 9 张表     │  │           │  │ +死信队列 DLQ│
  └────────────┘  └───────────┘  └──────┬───────┘
                                        ▼
                                  SMTP 邮件（可选）

关键点：Nginx 与应用同机、应用只监听回环；HTTPS 由 Nginx 终止，Spring Boot 不处理 TLS；`/uploads/**` 已被 Spring Security 放行，Nginx 用 alias 直接读盘以减轻 Java 压力。

## 一、Linux 生产部署完整步骤
### 1.1 创建运行账号与目录规划
应用禁止用 root 运行：上传、模板渲染都面对外部输入，低权限账号可限制被利用后的影响面。

```bash
sudo useradd -r -s /sbin/nologin netguard          # systemd 单元 User=netguard
sudo mkdir -p /opt/netguard/{uploads,logs,backup}
sudo chown -R netguard:netguard /opt/netguard
sudo chmod 750 /opt/netguard && sudo chmod 755 /opt/netguard/uploads   # nginx 需可读
# uploads 上传图片（yyyy/MM）｜logs logback 日志｜backup 旧 jar 与 SQL dump
```
### 1.2 准备应用 jar
```bash
# 开发机构建（见第四章），产物固定为 target/netguard.jar（pom 的 finalName=netguard）
scp target/netguard.jar deploy/netguard.service deploy/nginx.conf deploy/deploy.sh root@<服务器IP>:/tmp/

sudo install -m 0644 -o netguard -g netguard /tmp/netguard.jar /opt/netguard/netguard.jar
sudo install -m 0755 /tmp/deploy.sh /opt/netguard/deploy.sh
sudo install -m 0644 /tmp/netguard.service /etc/systemd/system/netguard.service
sudo install -m 0644 /tmp/nginx.conf /etc/nginx/conf.d/netguard.conf
unzip -l /opt/netguard/netguard.jar | head -n 5      # 应含 BOOT-INF/，确认 fat jar 完整
```
### 1.3 初始化数据库
```bash
sudo yum install -y mysql-server && sudo systemctl enable --now mysqld    # Ubuntu: apt/mysql
# 脚本自带 CREATE DATABASE netguard 与 USE netguard
mysql -u root -p --default-character-set=utf8mb4 < sql/netguard.sql

# 应用通过 127.0.0.1 TCP 连接，授权 host 必须匹配（'localhost' 与 '127.0.0.1' 是两条授权）
mysql -u root -p -e "CREATE USER IF NOT EXISTS 'netguard'@'127.0.0.1' IDENTIFIED BY 'netguard123'; GRANT ALL PRIVILEGES ON netguard.* TO 'netguard'@'127.0.0.1'; FLUSH PRIVILEGES;"

# 验证：9 张表 + 默认账号
mysql -u netguard -p -h 127.0.0.1 netguard \
  -e "SHOW TABLES; SELECT username,role FROM sys_user; SELECT @@character_set_database;"
```
> 跨机器迁移数据一律用 `mysqldump` 逻辑备份，不要直接拷贝 MySQL 数据目录。

### 1.4 配置 .env 环境变量清单
systemd 单元通过 `EnvironmentFile=/opt/netguard/.env` 注入变量，应用以 `--spring.profiles.active=prod` 加载 `application-prod.yml`。

```bash
sudo tee /opt/netguard/.env >/dev/null <<'ENV'
MYSQL_HOST=127.0.0.1
MYSQL_USER=netguard
MYSQL_PASSWORD=netguard123
MYSQL_DATABASE=netguard
REDIS_HOST=127.0.0.1
REDIS_PORT=6379
REDIS_PASSWORD=
RABBITMQ_HOST=127.0.0.1
RABBITMQ_PORT=5672
RABBITMQ_USER=netguard
RABBITMQ_PASSWORD=netguard123
RABBITMQ_VHOST=/
MAIL_HOST=smtp.example.com
MAIL_PORT=465
MAIL_USERNAME=alert@example.com
MAIL_PASSWORD=
ENV
sudo chown netguard:netguard /opt/netguard/.env && sudo chmod 600 /opt/netguard/.env
```

| 变量 | 应用是否读取 | 示例 | 说明 |
| --- | --- | --- | --- |
| `MYSQL_PASSWORD` | **是** | `netguard123` | prod 中 `${MYSQL_PASSWORD:netguard123}`，生产必须覆盖 |
| `MYSQL_HOST` / `MYSQL_USER` / `MYSQL_DATABASE` | 否（仅脚本） | `127.0.0.1` / `netguard` / `netguard` | prod 的 URL 与用户名硬编码；deploy.sh 备份时读取 |
| `REDIS_HOST` / `REDIS_PORT` / `REDIS_PASSWORD` | **是** | `127.0.0.1` / `6379` / 空 | 无认证则密码留空 |
| `RABBITMQ_HOST` / `PORT` / `USER` / `PASSWORD` / `VHOST` | **是** | `127.0.0.1` / `5672` / `netguard` / … / `/` | 须与 `rabbitmqctl add_user` 一致 |
| `MAIL_HOST` / `PORT` / `USERNAME` / `PASSWORD` | **是** | `smtp.example.com` / `465` / … / 授权码 | 465 走 SSL，授权码非登录密码 |

注意：只能写纯 `KEY=VALUE`（不能 `export`，等号两边无空格）；systemd 不做 shell 展开；值含空格或 `#` 用双引号；`.env` 不入 Git。想让 `MYSQL_HOST/USER` 真正生效需改 `application-prod.yml` 并重新打包，本版本未支持。

### 1.5 安装与托管
```bash
sudo systemctl daemon-reload && sudo systemctl enable --now netguard
sudo journalctl -u netguard -f            # 应出现 Started NetGuardApplication，且无 ERROR
curl -I http://127.0.0.1:8080/login        # 期望 200
cd /opt/netguard && sudo ./deploy.sh deploy  # 首次部署推荐：自带备份 + 健康检查

# Nginx（证书见第二章；先 nginx -t 再启动）
sudo yum install -y nginx
sudo mkdir -p /etc/nginx/ssl
sudo cp deploy/nginx.conf /etc/nginx/conf.d/netguard.conf
sudo nginx -t && sudo systemctl enable --now nginx
```
### 1.6 防火墙放行
```bash
sudo firewall-cmd --permanent --add-service=http --add-service=https && sudo firewall-cmd --reload  # firewalld
sudo ufw allow 80/tcp && sudo ufw allow 443/tcp && sudo ufw enable                                 # ufw
```
**不要对公网放行 8080**，应用只应由本机 Nginx 访问。需要更严格时可在 systemd 的 ExecStart 末尾追加 `--server.address=127.0.0.1`（改后 `daemon-reload` 并重启）。

## 二、Nginx 配置说明
配置来自 `deploy/nginx.conf`，安装到 `/etc/nginx/conf.d/netguard.conf`（该目录已被主配置 `http{}` 包含，不要整份覆盖 `nginx.conf`）。

| 配置段 | 作用 | 关键点 |
| --- | --- | --- |
| `upstream netguard_backend` | 后端节点池 | `127.0.0.1:8080`；`max_fails=3 fail_timeout=10s` 失败熔断；`keepalive 32` |
| 80 端口 server（注释） | HTTP 跳 HTTPS | `return 301 https://$host$request_uri`，保留路径与查询串 |
| `listen 443 ssl` | HTTPS 入口 | Nginx ≥1.25.1 用独立 `http2 on;`，旧版写 `listen 443 ssl http2;` |
| `ssl_protocols TLSv1.2 TLSv1.3` | 协议白名单 | 禁 TLS 1.0/1.1；`ssl_ciphers HIGH:!aNULL:!MD5:!RC4`；会话缓存 10m |
| `client_max_body_size 6m` | 请求体上限 | 应用限 5MB，Nginx 留 1MB 余量，避免 413 吞掉应用的友好提示 |
| `gzip on` + `gzip_types` | 压缩 | 只压 html/css/js/json/svg 等文本，图片字体不重复压 |
| `location ^~ /uploads/` | 上传图片直读 | `alias /opt/netguard/uploads/`、`expires 7d`、`autoindex off`；`^~` 防被正则抢走 |
| 静态资源 `location ~* \.(css|js|png|…)$` | 浏览器缓存 | `expires 7d`，仍回源后端（资源打包在 jar 的 `classpath:/static`） |
| `proxy_set_header Host` | 传递域名 | Security 生成跳转地址与 Cookie 域依赖它 |
| `X-Real-IP` / `X-Forwarded-For` / `X-Forwarded-Proto` | 真实 IP 与协议 | 后端日志、审计与绝对链接依赖 |
| `location = /nginx-health` | Nginx 自身探活 | `return 200 "ok\n"`，供监控/Keepalived 使用 |

**HTTPS 证书**：生产用受信任证书，放置为 `/etc/nginx/ssl/netguard.crt`（证书链，644）与 `/etc/nginx/ssl/netguard.key`（私钥，600，root 属主）。仅内网演示可用自签证书：

```bash
sudo openssl req -x509 -nodes -days 365 -newkey rsa:2048 \
  -keyout /etc/nginx/ssl/netguard.key -out /etc/nginx/ssl/netguard.crt \
  -subj "/C=CN/ST=Local/L=Local/O=NetGuard/CN=netguard.example.com"
sudo chmod 600 /etc/nginx/ssl/netguard.key
```
证书未就绪时：注释 443 块、启用配置中 80 端口临时 server 块，`nginx -t` 通过后对外；上线后恢复 301 跳转，避免凭据明文传输。修改后统一 `sudo nginx -t && sudo systemctl reload nginx`。

## 三、启动 / 停止 / 重启 / 查看日志
| 操作 | 命令 | 说明 |
| --- | --- | --- |
| 启动 | `sudo systemctl start netguard` | 启动后由 deploy.sh 做健康检查 |
| 停止 | `sudo systemctl stop netguard` | SIGTERM 优雅关闭，退出码 143 视为成功 |
| 重启 | `sudo systemctl restart netguard` | 改 `.env` 或 jar 后使用 |
| 状态 | `sudo systemctl status netguard` | 关注 `active (running)` 与最近日志 |
| 开机自启 | `sudo systemctl enable netguard` / `disable` | 生产必须 enable |
| 实时日志 | `sudo journalctl -u netguard -f` | systemd 收集的 stdout/stderr |
| 最近日志 | `sudo journalctl -u netguard -n 200 --no-pager` | 启动失败首选 |
| 应用日志 | `tail -f /opt/netguard/logs/netguard.log` | logback 落盘（LOG_DIR=./logs，工作目录 /opt/netguard） |
| 错误日志 | `tail -f /opt/netguard/logs/netguard-error.log` | 仅 ERROR，排障更快 |
| 健康检查 | `curl -I http://127.0.0.1:8080/login` | 200 表示 Tomcat 与 Spring 上下文就绪 |

> 本项目使用自定义 `logback-spring.xml`，日志位置由其中 `LOG_DIR=./logs` 决定；`application-prod.yml` 的 `logging.file.name` 只对 Spring Boot 默认日志配置生效。`WorkingDirectory=/opt/netguard` 使实际日志为 `/opt/netguard/logs/netguard.log`。

### 6.3 数据库备份与日志清理
```bash
# 事务一致性快照，不锁表；MYSQL_PWD 避免密码出现在 ps
MYSQL_PWD='netguard123' mysqldump -h127.0.0.1 -unetguard \
  --single-transaction --set-gtid-purged=OFF --default-character-set=utf8mb4 \
  netguard | gzip > /opt/netguard/backup/netguard-sql.$(date +%F).sql.gz

# /etc/cron.d/netguard-backup：每天 02:30 备份
# 30 2 * * * netguard MYSQL_PWD='netguard123' mysqldump -h127.0.0.1 -unetguard --single-transaction --set-gtid-purged=OFF netguard | gzip > /opt/netguard/backup/netguard-sql.$(date +\%F).sql.gz
find /opt/netguard/backup -name 'netguard-sql.*.sql.gz' -mtime +30 -delete   # 保留 30 天
sudo journalctl --vacuum-size=500M && sudo journalctl --vacuum-time=14d      # journald 限额清理
```
> logback 已按 20MB/文件、30 天、总量 500MB 自动滚动，一般无需手工删应用日志。

## 七、监控与告警
### 7.1 应用日志关键字
| 关键字（日志原文片段） | 含义 | 处置 |
| --- | --- | --- |
| `系统异常 [GET]` / `系统异常 [POST]` | 未捕获异常，用户见 500 | 抓堆栈，见 8.6 |
| `APPLICATION FAILED TO START` | 启动失败 | 看紧邻原因，见 8.1/8.2 |
| `Redis 不可用，已自动降级为本地内存缓存` | Redis 故障降级 | 见 8.3 |
| `RabbitMQ 投递失败，降级为本地同步通知` | MQ 不可用 | 见 8.4 |
| `告警邮件发送失败` / `告警邮件发送异常` | SMTP 失败 | 见 8.5 |
| `自动巡检执行失败` / `巡检调度器初始化失败` | 巡检异常 | 见 8.8 |
| `保存设备图片失败` / `创建上传目录失败` | 上传异常 | 见 8.7 |

### 7.2 端口与进程存活
```bash
ss -lntp | grep ':8080\b'                      # 端口监听
pgrep -af 'java .*netguard.jar'                # 进程
curl -s -o /dev/null -w '%{http_code}\n' --max-time 3 http://127.0.0.1:8080/login   # 200 才算就绪
```
可在 systemd `[Unit]` 追加 `OnFailure=netguard-alert@%n.service` 接入告警网关。

### 7.3 MySQL 连接数
```sql
SHOW STATUS LIKE 'Threads_connected';     -- 当前连接
SHOW STATUS LIKE 'Threads_running';       -- 执行中
SHOW VARIABLES LIKE 'max_connections';
SHOW PROCESSLIST;                         -- 定位卡住的 SQL
```
Hikari 配置 `minimum-idle=10`、`maximum-pool-size=30`；`Threads_connected` 长期 >30 或逼近 `max_connections` 时查事务未提交、流式查询未关闭等连接泄漏。

### 7.4 RabbitMQ 队列深度
```bash
rabbitmqctl list_queues name messages messages_ready messages_unacknowledged consumers
rabbitmqctl list_queues name messages | grep -E 'netguard.alarm.(queue|dlq)'
```
业务队列持续增长 → 消费者异常或邮件阻塞；`netguard.alarm.dlq` 有消息 → 必须逐条排查（管理台 15672 看 payload）；`consumers=0` → 应用未连上 broker。

### 7.5 建议阈值
| 指标 | 阈值 | 动作 |
| --- | --- | --- |
| 磁盘使用率 | >80% | 清日志/备份，扩容 |
| 健康检查非 200 | 持续 2 分钟 | 告警并尝试重启 |
| MySQL `Threads_connected` | >24（池上限 80%） | 查慢 SQL/泄漏 |
| 业务队列深度 | >100 持续 10 分钟 | 查消费者与 SMTP |
| ERROR 日志 | >10 条/分钟 | 立即人工介入 |

## 八、故障排查手册
### 8.1 启动失败：端口被占用
**现象**：`APPLICATION FAILED TO START`、`Web server failed to start. Port 8080 was already in use.`，`systemctl status` 反复 `activating (auto-restart)`。
**原因**：8080 被其他 Java 进程、未走 systemd 的旧实例或容器占用；上一实例优雅关闭超时未释放。
**处置**：
```bash
ss -lntp | grep ':8080\b'          # 找到 PID
ps -fp <PID>                       # 确认进程身份
sudo systemctl stop netguard && sudo pkill -f 'java .*netguard.jar'   # 清理残留
sudo systemctl start netguard
```
确需换端口：`--server.port=8081`，并同步改 Nginx `upstream` 后 `nginx -t && systemctl reload nginx`。

### 8.2 启动失败：数据库连不上
**现象**：`HikariPool-1 - Exception during pool initialization`、`Communications link failure` 或 `Access denied for user 'netguard'@'localhost'`；登录后 500。
**原因**：MySQL 未启动/3306 不通；库未导入；`.env` 密码错误或特殊字符未加引号；账号 host 不匹配（`'netguard'@'127.0.0.1'` 与 `@'localhost'` 是两条授权）；连接数打满。
**处置**：
```bash
systemctl status mysqld && ss -lntp | grep 3306
mysql -u netguard -p -h 127.0.0.1 netguard -e "SELECT 1;"
mysql -u root -p -e "CREATE USER IF NOT EXISTS 'netguard'@'127.0.0.1' IDENTIFIED BY '<密码>'; GRANT ALL ON netguard.* TO 'netguard'@'127.0.0.1'; FLUSH PRIVILEGES;"
sudo systemctl restart netguard
```
### 8.3 Redis 连接失败（已自动降级内存）
**现象**：日志 `Redis 不可用，已自动降级为本地内存缓存；每 60 秒尝试重连`，页面设备状态仍可显示；恢复后出现 `Redis 已恢复连接，缓存重新切换为 Redis`。
**原因**：Redis 未安装/未启动/端口密码错误；网络隔离；绑定 127.0.0.1 但应用在别的机器。
**处置**：
```bash
systemctl status redis
redis-cli -h 127.0.0.1 -p 6379 ping            # 期望 PONG
redis-cli -h 127.0.0.1 -p 6379 -a '<密码>' ping
```
核对 `.env` 的 `REDIS_HOST/PORT/PASSWORD` 后重启应用。单机降级不影响功能正确性；**多实例**时内存缓存不一致，必须修复 Redis 或统一改 `app.cache-mode=memory`。

### 8.4 RabbitMQ 连不上（MQ 降级/关闭）
**现象**：日志反复连接 `127.0.0.1:5672` 并出现 `RabbitMQ 投递失败，降级为本地同步通知`；`list_queues` 看不到 `netguard.alarm.queue` 或消费者为 0。
**原因**：broker 未启动、5672/15672 未开放、`.env` 账号与 `rabbitmqctl add_user` 不一致、vhost 无权限。
**处置**：
```bash
systemctl status rabbitmq-server
sudo rabbitmqctl add_user netguard '<密码>'
sudo rabbitmqctl set_permissions -p / netguard ".*" ".*" ".*"
sudo rabbitmqctl list_queues name messages consumers
```
发布者捕获 `AmqpException` 后直调 `NotifyService`，**告警不丢**，仅失去削峰与重试。长期不部署 MQ 时可加 `--app.mq.enabled=false` 走纯本地通知，减少日志噪音。

### 8.5 邮件发送失败
**现象**：`告警邮件发送失败：...` 或 `告警邮件发送异常：...`；通知记录中邮件状态失败，但告警已正常落库。
**原因**：SMTP 主机/端口错误；用了登录密码而非**授权码**；465 需 SSL 但被防火墙拦截；发件域名被 SPF/DKIM 拒；`app.mail.enabled=false` 时日志为"邮件通道未启用或未配置，跳过发送"。
**处置**：
```bash
nc -zv smtp.example.com 465                              # 连通性
openssl s_client -connect smtp.example.com:465 -quiet    # TLS 握手
```
核对 `.env` 的 `MAIL_*`（QQ/163 用授权码）与 `spring.mail.properties.mail.smtp.ssl.enable=true`。邮件在异步线程池发送，**不阻塞告警创建**；失败可在通知页手工重发或等下次告警。

### 8.6 页面 500
**现象**：浏览器显示 `error/500` 或"服务器开小差了，请稍后重试"；日志出现 `系统异常 [GET] /devices` 及堆栈。
**原因**：SQL 错误（字段/表不存在、类型不匹配）、Thymeleaf 表达式异常、空指针、数据库连接中断、上传路径不可写。
**处置**：
```bash
sudo grep -A 40 '系统异常' /opt/netguard/logs/netguard-error.log | tail -n 60
curl -i -b 'JSESSIONID=<值>' http://127.0.0.1:8080/devices      # 复现
mysql netguard -e "SHOW CREATE TABLE device\G"                  # 排查 SQL 字段
```
注意 `/api/**` 的 AJAX 失败返回 JSON（含 `code/message`）而非 500 页面；模板里一个属性写两个 `${}` 参与三元不会 500，但会原样输出导致页面错乱。

### 8.7 上传失败
**现象**：提示"图片大小不能超过 5MB"或"图片保存失败，请稍后重试"；也可能 Nginx 直接 413。
**原因**：超过 5MB（应用）或 6MB（Nginx）；扩展名不在 `jpg/jpeg/png/gif` 白名单；`/opt/netguard/uploads` 属主错误或磁盘满；Nginx `client_max_body_size` 被调小。
**处置**：
```bash
ls -ld /opt/netguard/uploads && df -h /opt
sudo chown -R netguard:netguard /opt/netguard/uploads
grep -n 'client_max_body_size' /etc/nginx/conf.d/netguard.conf
sudo tail -n 50 /var/log/nginx/netguard.error.log      # 413 / 权限错误
```
应用还有 `max-request-size: 10MB`，多图同表单时以请求体总大小为准。

### 8.8 定时巡检不执行
**现象**：设备状态长时间不刷新，`inspect_log` 无新批次；日志无 `自动巡检已排程` 或停在 `自动巡检已关闭`。
**原因**：规则页关闭了自动巡检；间隔不在 5/10/30 允许值；上一轮未结束被跳过（`上一轮巡检尚未结束，本次跳过`）；线程池阻塞；设备表为空。
**处置**：
```bash
sudo grep -E '动态巡检调度器|自动巡检|上一轮巡检' /opt/netguard/logs/netguard.log | tail -n 20
mysql netguard -e "SELECT id,rule_name,auto_inspect,inspect_interval FROM alarm_rule;"
mysql netguard -e "SELECT id,batch_no,trigger_type,start_time,end_time,total_count,fail_count FROM inspect_log ORDER BY id DESC LIMIT 5;"
```
规则改动经 `RuleChangedEvent` 热重排、无需重启；若日志完全没有调度器启动记录，检查 `巡检调度器初始化失败：...` 并确认设备表非空。手工触发可用 ADMIN 在巡检页点"立即巡检"（`POST /inspect/run`）。

## 九、升级与回滚流程
发版窗口选业务低峰（如 22:00 后）。单实例升级期间服务不可用约 20~40 秒（启动 + 健康检查）。

### 9.1 升级步骤
1. **构建**：开发机按 4.1 构建，记录代码/配置/SQL 变更；
2. **预检与备份**：`sudo /opt/netguard/deploy.sh preflight`，`deploy` 会自动备份旧 jar + `mysqldump`；
3. **上传**：`scp target/netguard.jar root@<IP>:/tmp/netguard.jar`，不要直接覆盖运行中的 jar；
4. **发布**：`cd /opt/netguard && sudo ./deploy.sh deploy /tmp/netguard.jar`（备份 → 停服 → 发布 → 启动 → `/login` 返回 200）；
5. **验证**：登录 → 看板 → 设备列表 → 手动巡检 → 告警确认 → 通知记录；`journalctl -u netguard -n 100` 无 ERROR；
6. **观察**：15 分钟内复查 ERROR 日志、队列深度、MySQL 连接数。

**SQL 变更**：项目未引入 Flyway/Liquibase，表结构变更随包提供增量脚本并在停服窗口手工执行；升级前先备份，优先"加列"等可回滚变更，避免直接 DROP。

### 9.2 回滚步骤
```bash
cd /opt/netguard && sudo ./deploy.sh rollback          # 恢复 backup/ 最新 jar 并重启（含健康检查）
MYSQL_PWD='<密码>' mysqldump -h127.0.0.1 -unetguard --single-transaction netguard \
  | gzip > /tmp/before-rollback-$(date +%F-%H%M).sql.gz # 表结构回退前先备份当前库
curl -s -o /dev/null -w '%{http_code}\n' http://127.0.0.1:8080/login
sudo journalctl -u netguard -n 50 --no-pager
```
**注意**：`rollback` 只回滚 jar，**不自动回滚数据库**——盲目导入旧 SQL 会丢失新产生的告警/巡检数据，数据库回退须单独评估。若回滚后仍失败，问题多在环境（数据库/Redis/端口），按第八章排查。

目标：验证备份可用并明确 RPO/RTO。课程环境建议 RPO ≤24 小时（每日 02:30 备份）、RTO ≤30 分钟（导入 + 启动）。

| 应用 jar | `/opt/netguard/backup/netguard.jar.<时间戳>` | 每次 deploy | 最近 5 个（脚本自动清理） |

### 10.2 真实灾难恢复（生产库损坏）
