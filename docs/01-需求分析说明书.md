# 01 需求分析说明书

> 项目名称：NetGuard 网络故障告警监控平台
> 对应题目：期末综合大作业 题目七（网络故障告警监控平台，难度 ★★★★☆）
> 文档版本：v1.0　编写日期：2026-11-24

## 1. 项目背景

企业网络中交换机、防火墙、服务器等设备数量多、分布广，传统人工巡检存在三个突出问题：

1. **发现晚**：设备离线往往由业务方先反馈，运维才被动响应，故障平均发现时间以小时计；
2. **无记录**：故障处理过程靠口头或聊天工具沟通，事后无法复盘，也无法统计设备稳定性；
3. **易漏判**：单次 Ping 失败可能只是网络抖动，人工判断容易误报或漏报。

本项目构建一套**轻量级网络故障告警监控平台**：定时对全部登记设备做 TCP 端口 / ICMP 连通性探测，状态变化时通过 RabbitMQ 异步产生告警并通知运维人员，同时沉淀巡检记录、告警记录与统计数据，形成"发现—通知—确认—恢复—复盘"的闭环。

## 2. 角色与权限

| 角色 | 标识 | 可执行操作 |
| --- | --- | --- |
| 系统管理员 | `ADMIN` | 设备类型维护、设备注册与编辑删除、告警规则配置（巡检间隔/阈值/通知方式）、手动执行巡检、查看全部告警与统计 |
| 运维人员 | `OPS` | 查看监控看板、查看设备状态与巡检记录、查看告警列表与详情、**确认告警并填写处理情况**、查看通知中心、维护个人资料与密码 |

权限控制原则：**最小可用**。所有 `/types/**`、`/rule/**`、设备写操作、手动巡检均为管理员专属；运维人员访问将被拒绝并跳转 403 页面。

## 3. 功能需求

### 3.1 设备注册管理（F1）

- 录入字段：设备名称、设备编号、IP 地址、设备类型、监控端口、部署位置、是否重点监控、设备图片、备注；
- 设备列表支持关键字（名称/IP）、类型、状态、是否重点监控筛选，支持按离线次数/最近巡检时间/名称排序；
- 列表展示在线/离线/未知状态标识、最近巡检时间、离线次数、告警数；
- 支持编辑、删除设备（删除时同步清理缓存），支持对单台设备"立即探测"；
- 校验：设备编号与 IP 唯一，IP 必须符合 IPv4 格式，端口 1–65535（0 表示使用 ICMP Ping），图片 ≤5MB 且仅允许 jpg/jpeg/png/gif。

### 3.2 定时巡检（F2）

- 按告警规则中配置的间隔（5 / 10 / 30 分钟）自动巡检全部设备；
- 探测方式：`monitor_port > 0` 时使用 **TCP 端口连接探测**，否则使用 **ICMP Ping**；
- 单次探测超时取规则配置（默认 2000ms），连续失败次数达到阈值（默认 2 次）才判定离线，避免网络抖动误报；
- 每次巡检生成一个**巡检批次**（`inspect_log`）与若干**巡检明细**（`inspect_detail`），记录探测结果、耗时、失败原因；
- 实时状态写入 Redis Hash `netguard:device:status`（Redis 不可用时自动降级内存），页面读取不必频繁查库；
- 支持管理员手动触发一次全量巡检，也支持单台设备即时探测。

### 3.3 故障告警与通知（F3）

- 设备由在线（或未知）变为离线时产生 `OFFLINE` 告警，级别判定：**重点监控设备 + 规则开启紧急** → `URGENT`（紧急），否则 `NORMAL`（普通）；
- 告警写入数据库后，通过 RabbitMQ 发送消息异步解耦通知逻辑（`netguard.alarm.exchange` / `netguard.alarm.queue`），消费者落库页面通知并发送邮件；
- 通知方式由规则开关控制：**页面通知**（通知中心未读角标）与**邮件通知**（JavaMailSender，异步线程池发送）；
- 运维人员可**确认告警**并填写处理情况说明；重复确认被拒绝；
- 设备恢复在线时自动关闭该设备未关闭的离线告警（状态 `RECOVERED`，写入恢复时间与持续时长），并新插入一条 `RECOVER` 恢复通知记录；
- 恢复通知同样走 MQ 异步通道。

### 3.4 告警历史统计（F4）

- 告警列表：按时间倒序展示告警时间、设备、类型、级别、状态、持续时长、确认人；支持关键字、级别、状态、类型、时间范围组合查询与分页；
- 告警详情：展示告警内容、确认信息、处理说明、恢复时间，并以时间轴呈现处理进度；
- 统计报表：区间告警总数、待处理数、平均处理时长、**每日告警趋势**、**告警级别分布**、**近 6 个月趋势**、**设备故障次数排行 TOP10**（含紧急次数、累计时长、占比）；
- 每日零点后定时任务汇总前一日数据到 `daily_stat`，用于长期趋势与报表加速。

### 3.5 告警规则配置（F5）

- 巡检间隔：5 / 10 / 30 分钟三档（保存后**下一个巡检周期立即生效**，无需重启）；
- 失败阈值：1–5 次；
- 探测超时：500–10000 ms；
- 重点监控设备紧急级别开关；
- 通知方式开关：页面通知、邮件通知；
- 邮件接收人：英文逗号分隔，留空则回退为全部启用用户的邮箱；
- 巡检总开关：暂停/启用定时巡检。

### 3.6 辅助功能（F6）

- 登录/登出（Spring Security 表单登录，BCrypt 密码，单账号最大 1 个会话）；
- 通知中心：列表、未读筛选、单条已读、一键全部已读，导航栏未读角标 30 秒轮询；
- 个人中心：修改姓名/邮箱/手机号、修改密码（校验原密码）；
- 全局异常处理：业务异常友好提示，页面异常渲染 403/500 页面，AJAX 请求返回统一 JSON；
- 操作反馈：所有写操作使用 POST + 重定向 + 闪存消息，避免重复提交。

## 5. 用例说明（核心 3 个）

### UC-01 设备离线自动告警

- 参与者：系统（定时任务）、运维人员
- 前置条件：设备已登记且启用巡检
- 主流程：
  1. 定时任务按间隔启动巡检；
  2. 对每台设备执行 TCP/ICMP 探测，写入明细；
  3. 连续失败达到阈值 → 生成 `OFFLINE` 告警（判定级别）；
  4. 发布 MQ 消息 → 消费者写入页面通知并发送邮件；
  5. 运维人员在通知中心/告警列表看到未读角标与新告警；
  6. 运维人员打开告警详情，填写处理说明并确认，状态变为 `CONFIRMED`。
- 异常流：MQ 不可用 → 本地同步通知；邮件未配置 → 通知记录状态 `SKIPPED` 并记录原因。

### UC-02 巡检间隔在线调整

- 参与者：管理员
- 主流程：管理员修改规则巡检间隔为 10 分钟 → 保存 → 服务发布 `RuleChangedEvent` → 调度器取消原任务并按新间隔重新排程 → 页面提示保存成功。
- 约束：间隔只允许 5/10/30；暂停巡检时取消任务但保留规则。

### UC-03 设备恢复自动闭环

- 主流程：巡检探测成功且设备此前为离线 → 更新设备状态为在线、清零失败次数 → 查找该设备未关闭的离线告警 → 置 `RECOVERED` 并计算持续时长 → 插入 `RECOVER` 记录 → 发送恢复通知 → 看板"待处理告警"数量刷新。

## 6. 验收标准

1. `mvn clean package` 成功，`java -jar target/netguard.jar` 可启动；
2. `sql/netguard.sql` 可在 MySQL 8.0 一次性执行成功，含 9 张表、每表 ≥5 条测试数据、默认账号；
3. 登录 `admin/admin123` 可进入看板，`ops/ops123` 仅具备运维权限（访问 `/rule` 返回 403 页面）；
4. 设备增删改查、类型维护、规则保存均可用，且校验提示友好；
5. 手动巡检可生成批次与明细，离线设备可触发告警并进入通知中心；
6. 告警可确认、可恢复，统计报表图表正常渲染；
7. 关闭 Redis/RabbitMQ/SMTP 后系统仍可启动并完成上述主流程（降级）；
8. 交付物齐全：源码、SQL、开发文档、部署说明、答辩 PPT、开发日志。

## 7. 需求边界（不做的事）

- 不做多租户与组织架构管理；
- 不做 SNMP 深度采集（仅连通性探测）；
- 不做短信/钉钉/企业微信通知（预留 `NotifyChannelEnum` 扩展点）；
- 不做设备批量导入（可作为后续迭代）。
