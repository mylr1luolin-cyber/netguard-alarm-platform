# 07 开发执行步骤与里程碑

> 适用范围：NetGuard 网络故障告警监控平台从 0 到交付的全过程
> 配套文档：01 需求、02 架构、03 数据库、04 接口与页面、05 编码、06 安全、08 测试、09 部署
> 文档版本：v1.0　编写日期：2026-11-24

本文件是排期与执行的唯一依据：阶段划分、人天投入、里程碑、联调提测标准、缺陷时限与风险应对都以此为准。表中日期为**计划基线**（2026-11-10 周二 ~ 2026-11-24 周二，共 11 个工作日），实际执行记录以 `开发日志/` 为准，两者不一致时以开发日志复盘为准并回写本文件。

## 1. 团队与分工

5 人团队，按"公共层 + 两条业务线 + 页面 + 测试文档"切分，每人主责一块并对相邻模块做交叉评审。

| 代号 | 角色 | 主要职责 | 主责模块 | 交叉评审范围 |
| --- | --- | --- | --- | --- |
| R1 | 组长 / 架构 | 需求与设计定稿、公共层、安全框架、代码评审、进度把控 | `common`、`config`、`security`、`exception` | 全部模块 |
| R2 | 后端 A | 设备资产与巡检链路 | `DeviceType`、`Device`、`Inspect`、`ProbeUtils`、`DynamicInspectScheduler` | 告警/规则 |
| R3 | 后端 B | 告警、通知、统计、规则、看板与中间件降级 | `Alarm`、`Notify`、`AlarmRule`、`Dashboard`、`DailyStatJob`、`mq` | 设备/巡检 |
| R4 | 前端 / 页面 | Thymeleaf 模板、`style.css`、`app.js`/`dashboard.js`、ECharts、页面走查 | `templates/**`、`static/**` | 接口契约 |
| R5 | 测试 / 文档 | 用例与验收、缺陷跟踪、日志与文档、打包部署、答辩材料 | `docs/08`、`deploy/`、`开发日志/`、答辩 PPT | 全流程 |

工作原则：接口先定契约（`docs/04`）再并行开发；R4 不直接改 Service，R2/R3 不改公共样式；跨人改动必须先在群里同步并在开发日志"关键决策"记录。

## 2. 开发流程总览

```
需求分析 → 架构与数据库设计 → 建库 → 工程骨架 → 公共层/安全 → 模块开发 → 前后端联调
    → 系统测试与缺陷修复 → 打包 → 部署验收 → 文档归档与答辩
   （docs/01）  （docs/02、03）  （sql）  （pom、yml）  （common/config）  （8 个模块）  （docs/04 契约）
```

每个阶段结束必须满足"验收标志"才进入下一阶段，不允许把未验收的产出带到下游；阶段产出物统一放 `docs/`、`sql/`、`deploy/`、`开发日志/`，不散落在个人目录。

```powershell
$env:JAVA_HOME='D:\devtools\jdk17\jdk-17.0.2'
$env:MAVEN_OPTS='-Dfile.encoding=UTF-8'
$env:PATH="$env:JAVA_HOME\bin;D:\devtools\maven\apache-maven-3.9.9\bin;$env:PATH"

# ② 生成工程骨架：pom.xml（parent 2.7.18、finalName=netguard、Java 17）

# ③ 首次构建
```

### 4.3 S3 公共层与安全（D4–D5）

按依赖顺序开发，每完成一项立即在 dev 环境自测：

| 顺序 | 内容 | 自测方式 |
| --- | --- | --- |
| 1 | `Result` / `ResultCode` / 业务枚举 / `CacheKeys` / `RuleChangedEvent` | 单元自测 + 接口返回结构 |
| 2 | `BusinessException` + `GlobalExceptionHandler` | 触发业务异常看页面/AJAX 分流 |
| 3 | 9 个实体 + `MybatisPlusConfig`（分页、审计字段） | 任意单表分页查询 |
| 4 | `SecurityConfig` + `UserDetailsServiceImpl` + `LoginSuccessHandler` + `SecurityUtils` | admin/ops 登录、403、退出、会话互斥 |
| 5 | `WebMvcConfig`（上传映射）、`AsyncConfig`、`SchedulingConfig`、`JacksonConfig` | 时间格式、上传访问 |
| 6 | `logback-spring.xml`（控制台 + 滚动文件 + ERROR 文件） | `logs/netguard.log`、`logs/netguard-error.log` 生成 |
| 7 | `RabbitConfig` + `LocalAlarmEventPublisher` 降级 | dev 下 `app.mq.enabled=false` 走本地发布 |

验收：dev 启动后访问 `/login` 正常；错误密码提示"账号或密码错误"；退出后重定向 `/login?logout=true`；`logs/` 下两个日志文件生成。

### 4.4 S4 设备类型与设备（D5–D6）

```
设备类型：entity DeviceType → mapper + XML(countByTypeId) → service(唯一性/被引用禁删) → controller → type/list.html
设备：   entity Device → mapper DeviceMapper.xml(selectDevicePage) → FileService → DeviceService(编号/IP 唯一、探测状态缓存)
        → DeviceController → device/list.html、device/form.html → 图片上传与预览
```

每模块固定 6 步：建表字段核对 → entity/mapper → service 业务规则与事务 → controller + dto/query → 模板 → 造数据自测。验收：ADMIN 新增设备后列表与看板数量一致；重复编号/IP 被拦截；OPS 登录看不到"设备类型"菜单且直接访问 `/types` 得 403。

### 4.5 S5 巡检/告警/通知（D6–D7）

```
规则读取 → ProbeUtils(TCP 优先，端口 0 走 ICMP) → InspectService.runInspect（批次 + 明细，阈值 == 判定）
        → AlarmService（URGENT/NORMAL、PENDING、恢复闭环 RECOVERED + duration_minutes）
        → NotifyService（PAGE 记录 + MAIL 记录，失败 FAILED/SKIPPED）
        → AlarmEventPublisher（Rabbit 或 Local 降级）
```

关键自测：手动触发一次巡检（`POST /inspects/run`）能生成批次与明细；把某台设备 IP 改为不可达，连续失败达到阈值后产生一条离线告警；改回可达后原告警变 `RECOVERED` 并新增恢复通知；同一故障不重复产生告警（阈值用 `==`）。

### 4.6 S6 统计/规则/看板（D8–D9）

| 模块 | 开发要点 |
| --- | --- |
| 统计 | 时间范围查询、每日趋势、级别分布、近 6 月、故障 TOP10；`inspect_detail` 按批次查询走 `idx_log` |
| 规则 | 单行配置读取与保存、`RuleChangedEvent` 热重排调度器（`ScheduledFuture` 取消重建）、开关用 `select` 提交 1/0 |
| 看板 | `DashboardService` 聚合 + 30 秒缓存（Redis 降级内存）、`/api/dashboard/summary` 与 `/charts`、ECharts 本地渲染 |
| 每日汇总 | `DailyStatJob` 每日 00:10 汇总 + 历史回填 |

验收：改巡检间隔为 10 分钟后无需重启，下一轮按新间隔执行；看板 P95 < 300ms（缓存命中）；统计页日期区间切换后图表随之变化。

### 4.7 S7 联调与提测（D10）

1. 以 `docs/04` 路由总表逐条核对 Controller 映射与模板链接，核对表单校验与闪存提示；
2. 用 ADMIN、OPS 两个账号各走一遍全链路：登录 → 看板 → 设备 → 巡检 → 告警 → 统计 → 通知 → 规则 → 个人中心；
3. 缺陷登记到 `docs/08` 第 10 节的缺陷表（编号、用例、现象、原因、修复、状态）；
4. 生成提测包：`target/netguard.jar` + `sql/netguard.sql` + 测试账号 + 提交说明（变更点与已知问题）；
5. 提测准入 8 项全部通过才可交给 R5（见第 6 节）。

### 4.8 S8 测试与修复（D10–D11）

执行 `docs/08` 第 1–9 节用例，重点覆盖：认证与权限边界、CSRF 缺失、SQL 注入与 XSS 载荷、上传白名单与大小、告警恢复闭环、Redis/MQ/邮件缺失降级、错误页不暴露堆栈。缺陷按第 7 节分级处理，修复后必须回归原用例并抽查相邻用例。

### 4.9 S9 打包与部署（D11）

```powershell

mvn -B -DskipTests package
# ② 本机冒烟（dev 配置，确认包可用）
```

验收：生产配置下（`--spring.profiles.active=prod`）能登录、看板有数据、巡检与告警链路可用；`deploy/nginx.conf`、`deploy/netguard.service` 生效；备份任务与日志轮转可查。

- 模块自身单测/自测通过，接口按 `docs/04` 返回，字段名与 VO 一致；
- 页面无 500、日志无 ERROR；临时调试代码与 `System.out.println` 已清理；

- [ ] `mvn -B -DskipTests package` 成功，`target/netguard.jar` 为最新

## 7. 缺陷分级与修复时限

| 级别 | 定义 | 典型示例 | 响应时限 | 修复时限 | 回归要求 |
| --- | --- | --- | --- | --- | --- |
| 致命 | 系统不可用、数据丢失、安全漏洞 | 启动失败、登录不了、越权可删设备、SQL 注入成功 | 30 分钟 | 4 小时 | 必须回归，修复前不得提测 |
| 严重 | 核心功能不可用或无正确结果 | 巡检不产生批次、离线不告警、确认告警无效、看板全空 | 2 小时 | 1 个工作日 | 必须回归 + 相邻用例抽查 |
| 一般 | 功能可用但结果/交互有偏差 | 分页总数错误、筛选条件失效、闪存提示文案不一致、图表数据偏差 | 1 个工作日 | 3 个工作日 | 回归原用例 |
| 轻微 | 样式、文案、体验问题 | 对齐、间距、空状态缺失、提示语不统一 | 下一工作日 | 下个迭代或提测前 | 页面走查确认 |

缺陷流程：登记（编号/用例/现象/原因/修复/状态）→ 指派 → 修复 → 回归 → 关闭。致命与严重缺陷必须当天在开发日志"遇到问题与解决"记录原因，避免同类问题重复出现。

## 10. 每日站会与开发日志制度

### 10.1 每日站会

- 时间：每工作日 9:30，时长不超过 10 分钟，站立或线上语音，R5 记录；
- 每人回答三问：昨天完成了什么（可验收事项）、今天计划做什么、有无阻塞；
- 阻塞当场认领：环境类找 R1，接口契约类找 R1/R3，测试类找 R5；未解决的阻塞写入当天开发日志"遇到问题与解决"；
- 站会看板列：待办 / 进行中 / 待联调 / 待测试 / 已完成，每人同时最多 2 项"进行中"。

### 10.2 开发日志

按 `开发日志/README.md` 执行：一天一个文件 `开发日志/YYYY-MM-DD.md`，固定四个区块——今日完成、关键决策、遇到问题与解决、明日待办；不允许事后补记超过 1 天。

```markdown
# 2026-11-24 开发日志

## 今日完成
- [x] 设备列表分页与排序（DeviceController、DeviceMapper.xml）

## 关键决策
- 排序字段用 `<choose>` 白名单而不是 `${}` —— 避免 SQL 注入

## 遇到问题与解决
- 现象：Thymeleaf 三元表达式原样输出
  原因：一个属性里出现两个 `${}`
  解决：整个三元写进单个 `${}`，并用 #temporals.format

## 明日待办
- [ ] 补告警恢复闭环用例（R5，预计 2 小时）
```

提交规则：日志与代码同一次提交，message 形如 `docs(log): 2026-11-24 开发日志`；更新 `开发日志/README.md` 的日志索引表；里程碑节点在当日日志中标注"阶段：M3 核心业务闭环"。
