# 06 安全设计规范

> 适用范围：登录认证、会话、授权、CSRF、SQL 注入、XSS、文件上传、敏感信息与部署安全
> 配套文档：04 接口与页面（路由与表单）、05 编码规范（异常与日志）、09 部署运维手册
> 文档版本：v1.0　编写日期：2026-11-24

本规范面向"网络故障告警监控平台"课程项目，安全基线参照 OWASP Top 10 与 Spring Security 官方推荐做法。所有开发与评审以本文为准；`SecurityConfig`、上传、SQL、模板输出相关改动，提交前必须逐条对照第 12 节自测清单。

## 1. 安全目标与威胁模型

### 1.1 资产与信任边界

| 资产 | 位置 | 敏感度 |
| --- | --- | --- |
| 登录凭据（BCrypt 密文） | `sys_user.password` | 高 |
| 设备资产与网络拓扑 | `device`、`device_type` | 中 |
| 告警与巡检历史 | `alarm_record`、`inspect_log`、`inspect_detail` | 中 |
| 数据库/中间件连接口令 | `application-prod.yml` 环境变量 | 高 |

信任边界：浏览器 ⇄（HTTPS）⇄ Nginx ⇄ Tomcat ⇄ MySQL/Redis/RabbitMQ/SMTP；浏览器输入一律不可信，内网组件不对公网开放。

### 1.2 威胁与对策总览

| 威胁 | 典型场景 | 本项目对策 | 章节 |
| --- | --- | --- | --- |
| 身份伪造 | 猜测/撞库登录 | BCrypt 校验、统一失败提示、会话互斥 | 2、3 |
| 会话劫持 | JSESSIONID 泄露 | HttpOnly、SameSite=Lax、HTTPS、2 小时超时 | 2 |
| 越权访问 | OPS 调管理端 URL | URL 规则 + `sec:authorize` + 服务端复校验 | 4 |
| CSRF | 第三方页面自动提交表单 | Spring Security CSRF + `th:action` | 5 |
| SQL 注入 | 搜索框、排序参数 | 全部 `#{}`、`CONCAT`、排序白名单 | 6 |
| XSS | 设备名称/处理说明回显 | `th:text` 转义、禁用 `th:utext` | 7 |
| 恶意文件上传 | 上传脚本/超大文件 | 扩展名白名单、5MB、UUID 改名、目录隔离 | 8 |
| 敏感信息泄露 | 配置泄露、日志含密码 | 环境变量、日志脱敏、错误页兜底 | 10 |

## 2. 认证

### 2.1 登录流程

```
① GET  /login                    → 渲染 login.html（error/logout/expired 提示）
② POST /login                    → Spring Security UsernamePasswordAuthenticationFilter
③ UserDetailsServiceImpl.loadUserByUsername(username)
      ├─ 查无此人 → UsernameNotFoundException("账号或密码错误")
      ├─ status != 1 → DisabledException("账号已被停用，请联系管理员")
      └─ 正常 → 返回 LoginUser（authorities = ROLE_ + role.name()）
④ BCryptPasswordEncoder.matches(raw, hash) 校验
      ├─ 失败 → failureUrl: /login?error=true
      └─ 成功 → LoginSuccessHandler（更新 last_login_time → 跳转 /dashboard）
⑤ 受保护页面：SessionAuthenticationFilter 校验会话，maximumSessions(1) 互斥
```

表单字段固定为 `username` / `password`，与 `SecurityConfig` 的 `usernameParameter` / `passwordParameter` 一致；登录页提交按钮文案"登录"，不提供"记住我"（会话 2 小时足够演示，减少持久化凭据面）。

### 2.2 关键配置

完整配置见 `SecurityConfig`：URL 级规则见 4.3 表，会话策略见 2.3 表；`application.yml` 中 `server.servlet.session.timeout: 2h`、`server.servlet.session.cookie.http-only: true`、`same-site: lax`。

### 2.3 会话策略

| 策略 | 配置 | 行为 | 用户感知 |
| --- | --- | --- | --- |
| 单会话 | `maximumSessions(1)` | 同一账号仅保留一个有效会话 | 后登录者踢掉先登录者 |
| 不阻止登录 | `maxSessionsPreventsLogin(false)` | 新会话正常建立，旧会话被标记过期 | 旧页面下一次请求跳转 `/login?expired=true` |
| 过期提示 | `expiredUrl` + `AuthController` | 渲染 `errorMsg`："账号已在其它地方登录，当前会话已失效" | 明确的重新登录引导 |
| 空闲超时 | `session.timeout: 2h` | 2 小时无请求后会话失效 | 再访问需重新登录 |
| 退出 | `POST /logout` | 失效会话 + 删除 `JSESSIONID` Cookie | 跳转 `/login?logout=true`，提示"您已安全退出登录" |

约定：会话互斥是安全要求，不是缺陷。演示时 ADMIN 与 OPS 使用不同浏览器（或一个普通窗口 + 一个隐私窗口），避免互相踢下线。

### 2.4 登录失败处理

1. **页面提示不区分账号不存在与密码错误**：两种情况统一为"账号或密码错误，请重新输入"（`UsernameNotFoundException` 文案亦为"账号或密码错误"），避免通过响应差异枚举账号。
2. **禁用账号**：`SysUser.status = 0` 时抛 `DisabledException`，页面同样按登录失败处理，服务端日志记录禁用原因级别为 `warn`；不向浏览器回显"该账号已停用"之外的内部信息。
3. **失败不写密码**：任何日志都不得打印用户提交的明文密码；Controller/Service 不得把 `PasswordForm` 整体 `toString()` 输出。
4. **失败响应归一**：统一 `302 → /login?error=true`，不返回 500 或区分账号/密码的错误码。

```java
// UserDetailsServiceImpl 关键分支
if (user == null) throw new UsernameNotFoundException("账号或密码错误");
if (user.getStatus() == null || user.getStatus() != 1) throw new DisabledException("账号已被停用，请联系管理员");
return new LoginUser(user);
```

## 3. 密码安全

### 3.1 存储算法

| 项 | 规定 |
| --- | --- |
| 算法 | BCrypt，`new BCryptPasswordEncoder()`（默认强度 10），Bean 定义在 `SecurityConfig` |
| 存储长度 | `sys_user.password VARCHAR(100)`，BCrypt 密文固定 60 字符 |
| 密文格式 | `$2a$10$` + 22 字符盐 + 31 字符哈希 |
| 禁止 | 明文、MD5、SHA-1、Base64 等可逆编码、全项目统一的固定盐 |

已有密文示例（`sql/netguard.sql` 初始化数据，强度 10）：

```
$2a$10$15pzQZkkHNDW0IP0Ot7cWu5UgXiIBTFIAVM3yzXTkeiPloANswCPq   ← admin / admin123
$2a$10$TmSsauPKn94UURPuYUZ..uueHiTmEnQr8fTlv2bsD6CYdZcAr5c0i   ← ops   / ops123
```

初始账号仅供课程演示，交付部署前必须重置为强密码，并删除 `sql/netguard.sql` 的演示口令说明或改为由管理员初始化。

### 3.2 修改密码流程

个人中心"修改密码"（`POST /profile/password`）必须依次校验：

1. 两次新密码一致，否则 `BusinessException("两次输入的新密码不一致")`；
2. 新密码不能与原密码相同，否则 `BusinessException("新密码不能与原密码相同")`；
3. **校验原密码**：`passwordEncoder.matches(form.getOldPassword(), user.getPassword())` 失败则 `BusinessException("原密码不正确")`；
4. 新密码长度 6–32（`PasswordForm` 校验），`encode` 后再 `updateById`；
5. 成功后 `log.info("用户 {} 修改了登录密码", username)`，日志中不出现任何密码明文/密文。

### 3.3 其他约定

- 密码字段不出现在页面回显值中（`profile.html` 不渲染 `user.password`），修改密码表单三个输入框均为 `type="password"`、`autocomplete="off"`；
- 管理员重置密码：课程版本不提供"找回密码"页面，运维通过数据库脚本写入新的 BCrypt 密文（用 `BCryptPasswordEncoder.encode` 生成），禁止把明文写进 SQL 注释。

## 4. 授权

### 4.1 角色模型

| 角色 | 枚举值 | Spring 权限 | 定位 |
| --- | --- | --- | --- |
| 管理员 | `RoleEnum.ADMIN` | `ROLE_ADMIN` | 平台配置与设备资产维护 |
| 运维人员 | `RoleEnum.OPS` | `ROLE_OPS` | 日常监控、告警确认与处理 |

`LoginUser.getAuthorities()` 返回 `ROLE_ + role.name()`，因此模板与配置统一使用 `hasRole('ADMIN')`（不带 `ROLE_` 前缀），数据库只存 `ADMIN` / `OPS`。

### 4.2 权限矩阵

| 功能 | 路由 | ADMIN | OPS | 服务端控制点 |
| --- | --- | --- | --- | --- |
| 查看看板 | `GET /dashboard` | ✅ | ✅ | 登录即可 |
| 查看设备列表/详情 | `GET /devices` | ✅ | ✅ | 登录即可 |
| 新增设备 | `POST /devices` | ✅ | ❌ | `POST /devices/**` → ADMIN |
| 编辑设备 | `POST /devices/{id}` | ✅ | ❌ | 同上 |
| 删除设备 | `POST /devices/{id}/delete` | ✅ | ❌ | 同上 |
| 单台设备立即探测 | `POST /devices/{id}/check` | ✅ | ❌ | 同上 |
| 查看设备类型 | `GET /types` | ✅ | ❌ | `/types/**` → ADMIN |
| 维护设备类型 | `POST /types`、`POST /types/{id}`、`POST /types/{id}/delete` | ✅ | ❌ | 同上 |
| 查看巡检记录 | `GET /inspects`、`/inspects/{id}` | ✅ | ✅ | 登录即可 |
| 手动立即巡检 | `POST /inspects/run` | ✅ | ❌ | 需 URL 规则 + 方法内复校验（见 4.5） |
| 查看告警列表/详情 | `GET /alarms`、`/alarms/{id}` | ✅ | ✅ | 登录即可 |
| 确认告警 | `POST /alarms/confirm` | ✅ | ✅ | 登录即可 + 状态必须为 PENDING |
| 查看统计报表 | `GET /alarms/statistics` | ✅ | ✅ | 登录即可 |
| 查看通知中心 | `GET /notices` | ✅ | ✅ | 登录即可 |
| 标记通知已读 | `POST /notices/{id}/read`、`/notices/read-all` | ✅ | ✅ | 登录即可 |
| 查看规则 | `GET /rule` | ✅ | ❌ | `/rule/**` → ADMIN |
| 保存规则 | `POST /rule` | ✅ | ❌ | 同上 |
| 个人资料/修改密码 | `GET/POST /profile`、`POST /profile/password` | ✅ | ✅ | 登录即可，只能操作本人 |
| 用户管理 | `/users/**` | ✅（预留） | ❌ | `/users/**` → ADMIN；当前无控制器，规则预置 |

### 4.3 URL 级控制

`SecurityConfig` 的匹配顺序自上而下，先匹配先生效。修改路由时必须同步本表与配置：

| 规则 | 匹配 | 要求 |
| --- | --- | --- |
| 静态与登录 | `/login`、`/css/**`、`/js/**`、`/images/**`、`/fonts/**`、`/webjars/**`、`/uploads/**`、`/favicon.ico`、`/error` | 匿名可访问 |
| 管理端页面 | `/types/**`、`/rule/**`、`/users/**` | `ROLE_ADMIN` |
| 设备写操作 | `POST /devices/**` | `ROLE_ADMIN` |
| 巡检写操作 | `POST /inspect/run` | `ROLE_ADMIN`（路由与配置需对齐，见 13.1） |
| 其他 | `anyRequest()` | 已认证 |

### 4.4 页面级控制

侧边栏与操作按钮使用 `thymeleaf-extras-springsecurity5` 的 `sec:authorize`，OPS 登录后不渲染管理入口：

```html
<nav sec:authorize="hasRole('ADMIN')">
    <a th:href="@{/types}" th:classappend="${activeKey == 'types'} ? 'active'">设备类型</a>
    <a th:href="@{/rule}"  th:classappend="${activeKey == 'rule'} ? 'active'">告警规则</a>
</nav>

```

**页面级控制只影响体验，不构成安全边界**：攻击者可以直接构造 POST 请求，因此服务端必须有第 4.3 / 4.5 节的校验。

### 4.5 服务端复校验（防越权）

`@EnableGlobalMethodSecurity(prePostEnabled = true)` 已开启，两种写法任选其一，管理类动作必须至少做一种：

```java
// 写法一：方法级注解
@PreAuthorize("hasRole('ADMIN')")
@PostMapping("/{id}/delete")
public String delete(@PathVariable Long id, RedirectAttributes redirect) { ... }

// 写法二：方法内显式判断（与 URL 规则双重保险）
if (!SecurityUtils.isAdmin()) {
    throw new BusinessException(ResultCode.FORBIDDEN, "只有管理员可以执行该操作");
}
```

规则：

1. 新增管理类路由时，`SecurityConfig` 规则、`sec:authorize`、服务端复校验三者同步，缺一不可；
2. 只读接口不放松：`/alarms/{id}` 等详情页必须校验资源存在，不存在返回 404 语义（`BusinessException` + `error/500` 或 `error/403`），不能渲染空白页；
3. 拒绝访问时页面走 `error/403`，AJAX 返回 `Result.fail(ResultCode.FORBIDDEN)`，不泄露具体缺失的权限名。

### 4.6 403 与异常分流

- `AccessDeniedException` → `accessDeniedPage("/403")`；`GlobalExceptionHandler` 记录 `log.warn("越权访问被拦截：{} {}", method, uri)` 后按页面/AJAX 分流。
- 未登录 → 重定向 `/login`；认证成功但权限不足 → `error/403.html`（"没有访问权限，请联系管理员"），不显示堆栈。

## 5. CSRF

### 5.1 机制

Spring Security 默认启用 CSRF 防护：服务端在会话中保存 token，表单提交时校验 `_csrf` 参数。Thymeleaf 与 Spring Security 集成后，**`th:action` 会自动追加隐藏域**（`<input type="hidden" name="_csrf" value="...">`），例如 `<form th:action="@{/devices}" method="post">…</form>`；启动后可在页面源码中确认该隐藏域存在，缺失时 `POST` 返回 403。

### 5.2 强制规则

1. **写操作只允许 POST**，且表单必须用 `th:action`，禁止手写 `action="/devices"`（手写不会注入 token，上线后全部写操作 403）；
2. GET 不得产生副作用：删除、确认、已读、退出、巡检全部 POST；退出用 `POST /logout`（Spring Security 默认），页面用表单 + `th:action` 而不是 `<a href="/logout">`；
3. 页面 JS 不自行拼接写请求；如必须 `fetch`，从 `<meta name="_csrf" content="...">` 读取 token 放入 `X-CSRF-TOKEN` 请求头；
4. **禁止** `http.csrf().disable()`；如确需豁免（例如未来开放第三方回调），必须限定到具体路径、方法并记录评审结论。

### 5.3 REST API 的取舍

本项目的 `/api/**` 只有 `GET /api/dashboard/summary`、`GET /api/dashboard/charts`、`GET /api/notices/unread` 三个只读接口，不涉及 CSRF。将来新增写接口时按以下方案之一处理：

| 方案 | 做法 | 适用 |
| --- | --- | --- |
| 会话 + CSRF Token | 保持 Cookie 认证，前端从 meta 取 token 放请求头，服务端校验 `X-CSRF-TOKEN` | 同源前端（推荐） |
| 无状态 Token | 关闭 Session 认证，改用 Bearer Token 并关闭该路径 CSRF | 对外开放 API |
| 不推荐 | 全局关闭 CSRF 或 `@CrossOrigin("*")` + Cookie 认证 | 任何场景 |

## 6. SQL 注入防护

### 6.1 `#{}` 与 `${}` 的区别

| 写法 | MyBatis 处理 | 安全性 | 用途 |
| --- | --- | --- | --- |
| `#{param}` | 预编译参数绑定（`PreparedStatement.setXxx`） | 安全，参数不参与 SQL 解析 | 所有用户输入 |
| `${param}` | 字符串直接替换进 SQL | 危险，可注入 | 仅限代码内固定常量（本项目禁止） |

MyBatis 会把 `#{...}` 编译为 `?` 预编译绑定，用户输入只作为参数值参与查询，不参与 SQL 解析。

### 6.2 本项目约束

1. 全项目 Mapper XML 与注解 SQL **只使用 `#{}`**，当前 `resources/mapper/` 下不存在 `${}`；
2. 模糊查询统一 `LIKE CONCAT('%', #{keyword}, '%')`，不允许 `'%${..}%'`，也不允许 MySQL 的 `||`（在默认 SQL 模式下是逻辑或，不是字符串拼接）；
3. 排序字段来自请求参数，必须用 `<choose>` 映射为固定列名（`offline_count`、`last_check_time`、`device_name`），方向只允许 `ASC`/`DESC` 字面量分支；
4. 批量 `IN` 查询用 `<foreach collection="ids" item="id" open="(" separator="," close=")">#{id}</foreach>`，禁止拼字符串；
5. 分页、`LIMIT` 等数值参数交由 MyBatis-Plus 分页插件处理，不手写拼接；
6. 数据库账号最小权限：生产 `netguard` 账号只授予 `netguard` 库的 `SELECT/INSERT/UPDATE/DELETE`，DDL 由初始化脚本使用管理员账号执行；
7. SQL 异常不向页面输出（`GlobalExceptionHandler` 已兜底为"服务器开小差了，请稍后重试"），日志中的 SQL 参数不得包含密码等敏感值。

## 7. XSS 防护

### 7.1 Thymeleaf 转义规则

| 写法 | 行为 | 规定 |
| --- | --- | --- |
| `th:text="${value}"` | HTML 实体转义（`<` → `&lt;`） | 用户可控内容唯一允许的渲染方式 |
| `th:utext="${value}"` | 原样输出 HTML | **全项目禁用** |
| `th:attr`/普通属性 | 自动转义 | 可用于 `title`、`data-*` |
| `th:inline="javascript"` | 按 JS 字符串规则序列化转义 | 仅用于图表初始化数据 |

### 7.2 用户可控内容清单

| 来源 | 字段 | 展示位置 |
| --- | --- | --- |
| 设备表单 | `deviceName`、`location`、`remark`、`deviceCode` | 设备列表、详情、告警明细、看板 |
| 类型表单 | `typeName`、`typeCode` | 类型列表、设备筛选下拉 |
| 告警确认 | `handleRemark` | 告警详情时间线 |
| 个人资料 | `realName`、`email`、`phone` | 顶栏、个人中心、通知收件人 |
| 规则配置 | `mailReceivers` | 规则页回显 |
| 系统生成 | 告警 `content`、通知 `title`/`content` | 告警列表、通知中心、邮件正文 |

这些字段只允许通过 `th:text` 输出；如果未来引入富文本，必须先在服务端做 HTML 白名单净化，禁止直接 `th:utext`。

### 7.3 不同输出上下文

1. **HTML 文本节点**：`th:text` 转义即可；
2. **HTML 属性**：用 `th:attr` 绑定，禁止把用户输入拼进 `href`/`src`/`on*`；
3. **内联 JS**：只用 `th:inline="javascript"`，禁止 `"<script>var x = '" + 用户输入 + "'</script>"`；
4. **邮件 HTML**：邮件正文由 Java 拼接（`NotifyService.buildMailHtml`），拼接用户可控字段（设备名称、告警内容、处理说明）前必须 `HtmlUtils.htmlEscape(...)`，否则会在收件人邮箱中形成 XSS 或钓鱼链接；
5. **导出文件**（后续扩展 Excel）：对以 `= + - @` 开头的单元格做前缀转义，防止公式注入。

### 7.4 响应头辅助

生产环境建议通过 Spring Security `headers()` 或 Nginx 增加：

```
Content-Security-Policy: default-src 'self'; script-src 'self' 'unsafe-inline'; style-src 'self' 'unsafe-inline'; img-src 'self' data:
X-Content-Type-Options: nosniff
Referrer-Policy: same-origin
```

页面只引用本地 `/js`、`/css`、`/uploads` 资源（ECharts 本地化），因此 `default-src 'self'` 可直接生效；内联脚本（图表初始化）需要保留 `'unsafe-inline'`，后续可改为 nonce。

## 8. 文件上传安全

### 8.1 校验规则（`FileService`）

| 检查项 | 规定 | 实现 |
| --- | --- | --- |
| 大小上限 | 单文件 5MB | `MAX_SIZE = 5 * 1024 * 1024L` + 业务校验；`multipart.max-request-size: 10MB` 兜底 |
| 扩展名白名单 | `jpg`、`jpeg`、`png`、`gif` | `ALLOWED_EXTENSIONS`，取最后一个 `.` 之后转小写（`Locale.ROOT`） |
| 文件名 | 不保留原名 | `UUID.randomUUID().toString().replace("-", "") + "." + ext` |
| 存储目录 | 按年月分目录 | `yyyy/MM`，根目录 `app.upload.dir`（dev `./uploads`，prod `/opt/netguard/uploads`） |
| 返回路径 | 相对访问路径 | `/uploads/2026/11/8f3c....png`，由 `WebMvcConfig` 映射为静态资源 |
| 大小超限提示 | `"图片大小不能超过 5MB"` | `BusinessException(ResultCode.FILE_UPLOAD_ERROR, ...)` |
| 类型非法提示 | `"不支持的文件类型，仅允许 jpg/jpeg/png/gif"` | `BusinessException(ResultCode.FILE_TYPE_NOT_ALLOWED)` |

### 8.2 路径穿越防护

- 原始文件名不参与路径拼接，从根上消除 `../`；
- 上传根目录在启动时 `toAbsolutePath().normalize()` 并 `createDirectories`，子目录由 `uploadRoot.resolve(datePath)` 得到；
- 若将来需要保留原文件名，必须 `normalize()` 后校验 `path.startsWith(uploadRoot)`，否则拒绝；
- 上传目录与 Web 应用目录分离（prod 在 `/opt/netguard/uploads`），不放在 Tomcat 的 `webapps` 下。

### 8.3 执行权限与访问控制

1. 上传目录只存放图片，Nginx 对该目录只允许静态读取，禁止执行脚本；
2. `/uploads/**` 在 `SecurityConfig` 中 `permitAll`（设备图片不含敏感信息，便于页面与邮件引用）；若后续上传含敏感截图，必须改为鉴权后由 Controller 输出文件流；
3. Nginx 对 `/uploads/` 只允许静态读取，并 `deny` 掉 `.php`、`.jsp`、`.sh`、`.exe` 等可执行扩展名。

4. **建议增强**：仅校验扩展名可被伪造（把 `.jsp` 改名 `.jpg`）。生产应增加魔数校验（JPEG `FF D8 FF`、PNG `89 50 4E 47`、GIF `47 49 46 38`）或使用 `ImageIO.read` 解码验证；课程版本保留扩展名 + 大小校验，评审时注明该边界。

## 9. 越权与 IDOR

本项目的数据模型是"平台级共享"：所有登录用户都能看到全部设备与告警，不存在按用户隔离的归属字段（`device.create_by`、`inspect_log.operator` 仅用于审计）。因此越权防护按以下原则执行：

| 操作 | 校验点 | 说明 |
| --- | --- | --- |
| `GET /devices/{id}/edit` | 登录 + `POST /devices/**` 规则不覆盖 GET，需在方法内判断 ADMIN | 编辑页含设备完整信息 |
| `POST /devices/{id}`、`/{id}/delete` | URL 规则 ADMIN | 数据归属为平台，无个人归属校验 |
| `POST /devices/{id}/check` | URL 规则 ADMIN | 探测会改变设备状态 |
| `GET /alarms/{id}` | 登录 + 资源存在 | 告警详情对 ADMIN/OPS 均开放 |
| `POST /alarms/confirm` | 登录 + 状态必须 `PENDING` | 已确认/已恢复再确认返回 `ALARM_ALREADY_CONFIRMED` |
| `POST /notices/{id}/read` | 登录 + 记录存在 | 通知为全体可见，无个人归属（`receiver` 是展示字段） |
| `GET/POST /profile` | 只能操作 `SecurityUtils.currentUserId()` | 禁止从表单接收 `userId` 修改他人资料 |
| 所有 `{id}` 路径 | `id` 必须为正整数，服务端查不到即抛业务异常 | 防枚举 + 防空白页 |

约定：**任何以 `{id}` 为参数的操作都必须先由服务端查出资源再决定是否允许**，不能仅凭前端隐藏按钮。未来若引入多租户/区域隔离，需在 `device`、`alarm_record` 增加归属字段并在 Service 层做数据级校验（本项目不做）。

## 10. 敏感信息与配置安全

### 10.1 配置分层

| 环境 | 数据库口令 | Redis/RabbitMQ/邮件 | 要求 |
| --- | --- | --- | --- |
| dev | `root/123456`（本机） | 默认值，`app.mq.enabled=false`、`app.mail.enabled=false` | 只允许本机使用，不提交真实生产口令 |
| test | 独立库 `netguard_test`（3307） | 测试实例 | 与生产隔离 |
| prod | `${MYSQL_PASSWORD:...}` | `${REDIS_HOST}`、`${REDIS_PORT}`、`${REDIS_PASSWORD}`、`${RABBITMQ_HOST/PORT/USER/PASSWORD/VHOST}`、`${MAIL_HOST/PORT/USERNAME/PASSWORD}` | 全部通过环境变量注入，配置文件只保留占位默认值 |

生产启动前先把口令注入环境变量（如 `export MYSQL_PASSWORD='******'`），再 `java -jar netguard.jar --spring.profiles.active=prod`。

禁止：把真实口令提交到 Git、写进 `README`/答辩 PPT、在群聊中明文发送。生产口令由部署负责人通过服务器环境变量或 systemd `EnvironmentFile` 注入（环境变量文件权限 600）。

### 10.2 日志与错误信息

1. 日志脱敏规则见 05 文档第 8.3 节：不打印密码（明文/密文）、完整邮箱、完整手机号、Session ID、CSRF Token；
2. 页面错误页只显示"服务器开小差了，请稍后重试"或业务提示，不输出异常类名、SQL、堆栈、文件路径；
3. `GlobalExceptionHandler` 对 `Exception` 兜底时 `log.error` 打印堆栈供排查，但响应体固定文案；
4. 生产 `logging.level.root=warn`、`com.netguard=info`，禁止在生产开启 `debug`（会输出参数细节）。

### 10.3 会话 Cookie 补充

- 生产 HTTPS 下应设置 `cookie.secure: true`（且只通过 HTTPS 访问，避免 Cookie 被明文嗅探）；
- 退出登录必须失效会话并删除 `JSESSIONID`（`invalidateHttpSession(true)` + `deleteCookies("JSESSIONID")`）。

## 11. 传输安全与部署加固

### 11.1 HTTPS / Nginx 反向代理

生产必须由 Nginx 终止 TLS（TLS 1.2+，禁用 SSLv3/TLS 1.0/1.1），Tomcat 只监听内网回环或内网地址。配置要点：`listen 443 ssl http2` + 站点证书/私钥 + `add_header Strict-Transport-Security "max-age=31536000; includeSubDomains" always` + `X-Content-Type-Options`、`Referrer-Policy` 响应头；`location /` 反代到 `http://127.0.0.1:8080` 并透传 `Host`、`X-Real-IP`、`X-Forwarded-For`、`X-Forwarded-Proto`；另加一段 80 端口 `return 301 https://$host$request_uri`。

Tomcat 侧设置 `server.forward-headers-strategy: native`，否则重定向可能生成 `http://` 地址；`server.tomcat.remoteip.internal-proxies` 按反代网段配置。

### 11.2 响应头基线

| 响应头 | 现状 | 要求 |
| --- | --- | --- |
| `X-Frame-Options` | `headers().frameOptions().sameOrigin()`（告警详情弹窗需要 iframe 同源） | 保持；禁止 `ALLOWALL` |
| `X-Content-Type-Options: nosniff` | Spring Security 默认启用 | 保持 |
| `Cache-Control` | 受保护页面默认 `no-cache, no-store` | 保持，避免退出后浏览器回退看到敏感页面 |
| `Strict-Transport-Security` | 未配置（仅 HTTPS 下有意义） | 生产 Nginx 添加 |
| `Content-Security-Policy` | 未配置 | 生产评估后按 7.4 节添加 |
| `Referrer-Policy` | 未配置 | 生产 Nginx 添加 `same-origin` |

### 11.3 其他部署要求

1. MySQL、Redis、RabbitMQ 不做公网端口映射，只监听内网/回环；
2. 数据库账号最小权限（见 6.2 第 6 条），禁止生产使用 `root`；
3. `/actuator` 等运维端点如启用，必须限制内网访问并加认证；
4. 日志目录、上传目录、备份目录权限收敛到运行账号（非 root）；备份文件加密存储。
