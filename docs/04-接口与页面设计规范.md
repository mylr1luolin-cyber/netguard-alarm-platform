# 04 接口与页面设计规范

> 适用范围：`com.netguard.controller` 全部页面控制器与 `/api/**` JSON 接口
> 文档版本：v1.0　编写日期：2026-11-24

## 1. URL 设计原则

1. **资源化**：路径使用名词复数（`/devices`、`/alarms`、`/types`、`/inspects`、`/notices`），动作用 HTTP 方法或子路径表达（`/devices/{id}/check`、`/alarms/confirm`）；
2. **页面与小写连字符**：页面路径全小写，多词用 `-`（`/alarms/statistics`）；
3. **写操作只允许 POST**：受 CSRF 保护，避免 GET 产生副作用（爬虫/预取导致误删）；
4. **管理端统一前缀**：管理类页面直接挂在根下，JSON 接口统一 `/api` 前缀，便于安全规则集中配置；
5. **参数风格**：查询列表用 Query 对象接收（`?page=1&size=10&keyword=x`），不使用嵌套路径参数。

## 4. JSON 接口契约

统一响应体 `com.netguard.common.Result<T>`：

```json
{
  "code": 200,
  "message": "操作成功",
  "data": { },
  "timestamp": "2026-11-24 01:40:00"
}
```

| 字段 | 类型 | 说明 |
| --- | --- | --- |
| code | int | 200 成功；400 参数错误；401 未登录；403 无权限；404 不存在；500 服务异常；1001+ 设备类；2001+ 告警类；3001+ 规则类；4001+ 用户类 |
| message | string | 面向用户的提示语，可直接展示 |
| data | T | 业务数据，失败时为 `null` |
| timestamp | LocalDateTime | 服务端时间，格式 `yyyy-MM-dd HH:mm:ss` |

`/api/dashboard/charts` 的 `data` 结构：

```json
{
  "deviceTypes": [{ "name": "核心交换机", "value": 2 }],
  "status":     [{ "name": "在线", "value": 8 }],
  "trend":      [{ "name": "11-01", "value": 3 }],
  "levels":     [{ "name": "紧急", "value": 5 }],
  "faultRanks": [{ "name": "核心交换机-A", "value": 4 }]
}
```

> 约定：图表数据统一用 `name`/`value` 两字段，ECharts 侧 `names()`/`values()` 兼容 `label`/`count` 回退。

## 5. 表单校验规则

校验注解放在 `dto` 层（`javax.validation`），控制器用 `@Valid` + `BindingResult`，页面用 `#fields.hasErrors('field')` 逐字段回显。

| 表单 | 字段 | 规则 | 提示语 |
| --- | --- | --- | --- |
| DeviceForm | deviceCode | 非空，`^[A-Za-z0-9_-]+$`，≤50 | 设备编号只能包含字母、数字、下划线和短横线 |
| DeviceForm | deviceName | 非空，≤100 | 请填写设备名称 |
| DeviceForm | ipAddress | 非空，IPv4 正则 | 请填写合法的 IPv4 地址 |
| DeviceForm | deviceTypeId | 非空 | 请选择设备类型 |
| DeviceForm | monitorPort | 1–65535（0 表示 ICMP） | 端口需在 1-65535 之间 |
| DeviceTypeForm | typeName / typeCode | 非空；typeCode 唯一（转大写） | 类型编码已存在 |
| RuleForm | inspectInterval | ∈ {5,10,30} | 巡检间隔只支持 5/10/30 分钟 |
| RuleForm | failThreshold | 1–5 | 失败阈值需在 1-5 之间 |
| RuleForm | timeoutMs | 500–10000 | 超时时间需在 500-10000 毫秒之间 |
| RuleForm | mailReceivers | 开启邮件通知时必填，逗号分隔邮箱 | 开启邮件通知后必须填写接收人邮箱 |
| AlarmConfirmForm | handleRemark | ≤255，建议必填 | 请填写处理情况说明 |
| ProfileForm | email / phone | 邮箱格式；`^1[3-9]\d{9}$` | 手机号格式不正确 |
| PasswordForm | newPassword | 6–32 位，两次一致，且不同于旧密码 | 两次输入的新密码不一致 |

## 6. 列表查询与分页约定

- 统一参数：`page`（默认 1，从 1 开始）、`size`（默认 10，上限 100，服务端 `getLimit()` 截断）；
- 分页结果使用 MyBatis-Plus `IPage<T>`，模板中统一：`page.records`、`page.total`、`page.current`、`page.pages`；
- 分页链接必须携带其余查询条件，写法：

```html
<a th:href="@{/devices(page=${page.current - 1},
        size=${page.size}, keyword=${query.keyword},
        typeId=${query.typeId}, status=${query.status})}">上一页</a>
```

- 筛选条固定放页面顶部 `.filter-bar`，包含"查询"与"重置"两个动作，重置指向不带参数的当前路径；
- 排序参数 `sortField`（`offlineCount`/`lastCheckTime`/`deviceName`）+ `sortOrder`（`asc`/`desc`），XML 中通过 `<choose>` 白名单分支拼接，**禁止把参数直接拼进 ORDER BY**。

## 7. 闪存消息与错误页

- 写操作成功后：`redirectAttributes.addFlashAttribute("msg", "…")` + `("msgType", "success"|"danger"|"warning")`；
- 页面通过 `layout.html` 的 `flash(msg, msgType, errorMsg)` 片段统一渲染，4 秒后自动淡出；
- 表单校验失败时**不重定向**，直接回填 `model` 并渲染原模板（`redisplayForm`），保留用户输入；
- 全局异常：页面请求渲染 `error/403` 或 `error/500`，`model` 中带 `message`；AJAX 请求（`/api/**` 或 `X-Requested-With: XMLHttpRequest`）返回 `Result.fail(...)`。

## 8. 页面布局与前端规范

1. **模板继承**：每个页面 `th:replace="fragments/layout :: head('标题')"`，侧边栏 `sidebar('activeKey')`（activeKey 取值 `dashboard`/`devices`/`inspects`/`alarms`/`statistics`/`notices`/`types`/`rule`/`profile`），顶部 `topbar('标题','副标题')`；
2. **样式来源**：仅 `static/css/style.css` 一个自写样式表，不引入 Bootstrap 等外部框架；`static/js/echarts.min.js` 为本地图表库；
3. **禁止内联样式**控制布局，个别动态宽度（进度条）允许 `th:style`；
4. **Thymeleaf 表达式纪律**：
   - 单个 `${}` 内可写三元与 `#temporals.format`；**不得在一个属性里写两个 `${}` 参与三元**；
   - 禁用 `th:utext` 渲染任何用户输入；
   - 每个 POST 表单用 `th:action`（自动附加 CSRF 隐藏域），不使用手写 `action`；
5. **交互约定**：
   - 危险操作按钮加 `data-confirm="确认文案"`，由 `app.js` 接管二次确认；
   - 表格行需可点击时加 `data-href`，不嵌套 `<a>`；
   - 顶部铃铛每 30 秒轮询 `/api/notices/unread` 更新红点；
   - 看板图表每 60 秒自动刷新，`window.resize` 时重绘；
6. **空状态**：列表无数据时渲染 `.empty`（图标 + 标题 + 说明），不显示空表格；
7. **无障碍与可用性**：表单控件必须有 `<label>`；按钮文案使用动词（"保存规则"而非"提交"）；错误提示紧邻字段。

## 9. 状态与枚举展示映射

| 枚举值 | 展示文案 | CSS 类 |
| --- | --- | --- |
| `ONLINE` | 在线 | `badge b-online` |
| `OFFLINE` | 离线 | `badge b-offline` |
| `UNKNOWN` | 未知 | `badge b-unknown` |
| `URGENT` / `NORMAL` | 紧急 / 普通 | `b-urgent` / `b-normal` |
| `PENDING` | 待处理 | `b-pending` |
| `CONFIRMED` | 已确认 | `b-confirmed` |
| `RECOVERED` | 已恢复 | `b-recovered` |
| `CLOSED` | 已关闭 | `b-closed` |
| `MAIL` / `PAGE` | 邮件 / 页面 | `b-mail` / `b-page` |

> 新增枚举值时，必须同步《03-数据库设计说明书》字段说明与本表，避免页面出现未映射的裸值。
